# 轨道系统机制百科（星光自研）

> **⚠️ 命名真相（重要）**：星光自研的 `Railroading`（代码路径 `Content.Server/_Starlight/Railroading/`，24 个 C# 文件 + Shared 42 个）**并非轨道铺设/矿车运输系统**。"Railroading" 是英文俚语，指"把剧情强行固定在单一轨道上"（on rails）——**本系统是星光的"任务卡/剧情卡"系统**：班次中系统定期向玩家发放 3 张任务卡，玩家从中选 1 张执行，完成得信用点/快递奖励，失败则任务作废。本条目按源码实况撰写。
> 源码仓库中不存在任何"铺轨/矿车/轨道运输"实现（`Minecart`/`Rail` 相关检索无命中；`Resources/Prototypes/_Starlight/Entities/` 中 rail 命中均为误匹配，如眼镜/帽子 yaml 里的单词片段）。**星光服务器目前没有轨道建造机制**——工程部没有铺轨玩法，供应部也没有轨道货运联动；若玩家在服务器见过"轨道"，那不属于本 fork 的 `_Starlight/Railroading` 代码层。
>
> 基线 commit：`7f25e6829ec8a49be76d96c322c27dcf47a327a8`（2026-07-26，zh-cn 分支）

## 二、核心机制流程

### 2.1 一轮完整的"发卡 → 选卡 → 结算"流程

```
① 规则启动（RailroadRule 作为 StationEvent 被 GameTicker 激活）
      │
② 阶段机推进（RailroadRuleSystem.ActiveTick，RailroadRuleSystem.cs:56）
      │
③ 卡池构建（StaticSpawn/DynamicSpawn 阶段，按 RailroadSpawnFlow 概率/数量生成卡片实体）
      │
④ 洗牌 + 收集可发卡玩家（CardShuffle / PreCardIssuance 阶段）
      │
⑤ 发卡（CardIssuance 阶段）：每人 ≤3 张 → 弹 Alert「可进行挑战」
      │
⑥ 玩家点击 Alert → CardSelectionEui 卡牌选择窗口（RailroadingSystem.cs:119）
      │
⑦ 选 1 张 → 成为 ActiveCard（活跃卡），触发 Handler 事件（传真/公告/角色等）
      │
⑧ 任务判定（TaskSystem + Watcher 组件监听玩家事件，轮询完成度）
      │
⑨ 完成 → InvalidateProgress → 奖励结算（信用点/快递）；失败 → CardFailed
      │
⑩ CycleDelay 阶段等待 Delay 秒 → 回到 DynamicSpawn 循环（新卡片重新入池）
```

### 2.2 阶段机（RailroadRuleComponent.RailroadStage，`Components/RailroadRuleComponent.cs:51-61`）

| 阶段 | 行为 | 源码 |
|---|---|---|
| `PreSpawnDelay` | 等待 `PreSpawnDelay` 秒（默认 300s，见 :46） | `RailroadRuleSystem.cs:71-79` |
| `StaticSpawn` | 每 tick 生成 ≤10 张静态卡片实体（`Cards` 列表），`SpawnIndex` 推进 | :81-92 |
| `DynamicSpawn` | 每 tick 从 `DynamicCards` 队列取 ≤10 张生成（处理"选中卡后补卡"场景） | :94-105 |
| `CardShuffle` | 随机洗牌通用池 `Pool`（防连续同条件卡） | :110-116 |
| `PreCardIssuance` | 遍历所有 `RailroadableComponent` 实体，有玩家的入 `IssuanceQueue` | :118-129 |
| `CardIssuance` | 逐个发卡（见 2.3），队列空则进入 CycleDelay | :131-189 |
| `CycleDelay` | 等待 `Delay` 秒（默认 300s，RuleComponent:49）后回 DynamicSpawn | :191-199 |
| `Stopped` | 规则终止（同回合已有活跃规则时触发，:40-54） | — |

**规则互斥**：若已有活跃 RailroadRule，新规则把自己 `Cards` 全部并入旧规则的 `DynamicCards` 队列后自我终止（`Added`，:40-54）——保证同回合只有一条规则在跑。

### 2.3 发卡算法（CardIssuance，`RailroadRuleSystem.cs:131-189`）

每人每轮最多 **3 张**（`CardPerUser = 3`，:24）。组合规则：

1. **职业卡**（最多 1 张，放中间槽）：从 `PoolByJob`（按 JobPrototype 分池）随机取 1 张——注释说明职业卡放中间避免淹没在通用池（RuleComponent:32-35）
2. **目标卡**（最多 1 张）：从 `PoolByObjective`（按 Objective 原型分池，如影裔相关目标）取 1 张
3. **通用卡**：剩余槽位从通用池 `Pool` 随机补足

**发放条件**（:135-138）：玩家未 `Restricted`、`IssuedCards` 不足 3 张、无未删除的 ActiveCard。

**条件过滤**（`PopRandomFromPool`，:278-297）：抽卡时遍历卡片上的 `ConditionsComponent` 条件（`SubjectMindJobCondition`/`SubjectSpeciesCondition`/`SubjectMindAntagCondition` 等），全部满足才发放；最多尝试 `ProcessingMaxTry = 10`（:26）次。

**发卡后**：`ShowAlert` 弹「可进行挑战」警报（RailroadingSystem.cs:145-151；alert id `RailroadingChoice`，`_Starlight/Alerts/railroading.yml:2`）。

### 2.4 选卡与结算（RailroadingSystem.cs）

| 事件 | 行为 | 源码 |
|---|---|---|
| 点击 Alert `OpenCardsAlertEvent` | 打开 `CardSelectionEui`（每玩家同时只能开 1 个，`_openUis` dict） | :119-132 |
| 选卡 `CardSelectedMessage` | 校验卡片属于 IssuedCards → 触发 `RailroadingAssignedEvent`（可被取消）→ 设为 ActiveCard → 触发 Handler 的 `RailroadingCardChosenEvent`；选中罪犯卡额外解锁成就（见 2.6） | :153-199 |
| 关闭窗口 `CardSelectionClosedMessage` | 未选卡：普通玩家卡全部退回池子并标记 `Restricted`（本回合不再发卡）；`Important` 玩家（如影裔）可重开 | :200-214 |
| 完成轮询 `InvalidateProgress` | 向 ActiveCard 发 `RailroadingCardCompletionQueryEvent`，各 TaskSystem 应答 `IsCompleted`；全 true → `RailroadingCardCompletedEvent` → 奖励结算，卡片移入 `Completed` 列表 | :216-233 |
| 失败 `CardFailed` | 触发 `RailroadingCardFailedEvent`，卡片移入 `Completed`（失败也算"已处理"） | :235-248 |

### 2.5 管理员视角

管理员用 `examine` 查看带 `RailroadableComponent` 的玩家时，可看到当前 ActiveCard 与历史 IssuedCards 的颜色/图标/标题/描述（`:70-102`，`railroading-card-examined` / `railroading-issued-card` 文案）。所有选卡/完成/失败均写入管理日志（`LogType.Railroading`，LogImpact.Medium）。

### 2.6 成就联动（RailroadingSystem.cs:183-190）

选中的卡片原型为 `RRCardCriminal` 时，按玩家身份解锁成就：
- 有 `CommandStaffComponent`（指挥层）→ 成就 `wavering_loyalty`（动摇的忠诚）
- 其他玩家 → 成就 `on_the_run`（在逃）

## 八、疑点清单（⚠️ 如实记录）

1. **命名误导**：`Railroading` 实为任务卡系统，"轨道"仅是"强制剧情线"的俚语隐喻。**星光 fork 不存在轨道铺设/矿车运输玩法**——若任务书预期"铺轨机制"，本条目已按源码实况纠正。工程部/供应部与此系统无结构性联动（唯一交叉点是完成任务后经 DeliverySpawner 投递奖励包裹）。
2. **死卡片**：5 张酒精卡（DeadRum/Empress75/IrishBool/NTCahors/PoisonWine）+ 2 张影裔卡（Backup/DarkStation）+ 1 张测试卡（MetabolizeTest）定义了但未在任何规则卡池引用。`RRCardMetabolizeBaseAlcohol` 为抽象基类不计。即 140 个定义中实际可发 132 个，常用池 120（Minor）+ 9（Brighteye）+ 1（Terminate）。
3. **售货机秘密权限是"空壳"**：`RailroadSecretVendingAccessComponent` 仅 2 处引用（war.yml:46 标记 + RailroadingSystem.cs:116 读取 `HasSecretAccess` 传给 UI 显示），**没有任何消费该标记的售货机/商店逻辑**——逃兵卡的"自动售货机秘密区域访问权限"（rr-secret-access-hint）目前只是 UI 提示，无实际效果。
4. **`ShowAlert` 的 todo**：`RailroadingSystem.cs:144` 注释 `// todo: timer`——警报无自动消失计时器（zh-CN alerts.ftl 文案声称"若将其关闭，本回合内不会再次显示"，但 `Restricted` 标记才是防重发机制；关闭窗口≠点击警报，路径不同，行为待验证）。
5. **`OnCardSelected` 边界**：`subject.Comp.IssuedCards is null` 时直接 return（:159），此时选中卡不生效；foreach 中未命中选中卡的卡片逐个 `AddCardToPool` 回池（:195-196），与关闭窗口路径行为一致。
6. **被铐/死亡即失败**：罪犯卡与"避免手铐"任务耦合——任何 `TargetHandcuffedEvent` 都会判失败（AvoidHandcuffsTaskSystem.cs:33-42），包括安保正常执法场景，可能造成"不可抗力失败"。
7. **影裔卡无信用点奖励**：Brighteye 卡全部无 `RailroadDonationReward`，影裔的任务卡纯剧情导向；且 `Important: true`（events.yml:156 的 Brighteye mind 实体）使影裔可反复重开选卡界面。
8. **`RailroadingBrighteye` 规则互斥**：Brighteye 局内同时只允许 1 条 RailroadRule 活跃（RailroadRuleSystem.cs:40-54），若 Minor 事件已激活，Brighteye 卡会并入其动态池——两套卡池会混发。
9. **卡片实体生成于 Nullspace**（`MapCoordinates.Nullspace`，RailroadRuleSystem.cs:263）：卡片本身是"规则数据实体"，不占地图，删除后由 `AddCardToPool` 逻辑管理回池。
10. **成就与罪犯卡强绑定**：成就 `wavering_loyalty`/`on_the_run` 只在选中 `RRCardCriminal` 时解锁（RailroadingSystem.cs:183-190），是唯一成就联动点。
