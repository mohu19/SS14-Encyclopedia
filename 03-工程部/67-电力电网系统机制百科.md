## 1. 总览

SS14 的电力系统是**电网求解器（Pow3r）+ ECS 组件 + yaml 原型**三层结构，与 SS13 的电力完全不同：

- **物理层**：电缆（HV/MV/LV 三色）按节点组（NodeGroupID）形成电网；设备通过节点（CableDeviceNode / CableTerminalPortNode）挂网。
- **逻辑层**：`PowerNetSystem` 每 tick 把电网编译成 Pow3r 求解器状态（Supply / Load / Battery / Network 四类节点，`PowerState.cs:20-23`），由 `BatteryRampPegSolver` 求解功率分配。
- **数值层**：所有容量/功率/斜坡数值在实体原型 yaml 中定义，组件 DataField 默认值只在未覆写时生效。

**一句话机制**：发电机与电池按「斜坡（ramp）」逐步爬升至目标出力；每 tick 汇总全网需求与可用供应，若供应不足则**按比例均摊限电**；电池只在本地供应不足（unmet > 0）时补缺放电；SMES/变电站/APC 三级电池构成「HV→MV→LV」电压阶梯。

## 2. 电网层级（HV / MV / LV 电压网络）

### 2.2 电压转换链（三级变压器）

电力只能**逐级降压**，不能跨级直连：

```
发电机(如 RTG 10kW)
   │ HV 电缆
   ▼
SMES（HV→HV 缓冲储能，带电缆端子隔离输入/输出）
   │ HV 电缆
   ▼
变电站 Substation（HV 输入 → MV 输出，substation.yml:17-22）
   │ MV 电缆
   ▼
APC（MV 输入 → LV 输出，apc.yml:141-151 节点定义）
   │ LV 电缆（ExtensionCable 无线范围供电）
   ▼
灯具 / 电脑 / 自动机床 / 贩卖机 …
```

- **SMES**：输入走 `CableTerminalPortNode`（HVPower），输出走 `CableDeviceNode`（HVPower），`smes.yml:47-52`；电缆端子保证 HV 输入与输出不短路（`cable_terminal.yml:46-50` 双端子节点）。
- **变电站**：`input` 节点 HVPower、`output` 节点 MVPower，`substation.yml:16-22`。
- **APC**：`input` 节点 MVPower、`output` 节点 Apc，`apc.yml:141-151`。

### 2.3 LV 无线供电半径

LV 电缆带 `ExtensionCableProvider`（传输范围），机械带 `ExtensionCableReceiver`（接收范围），两者都满足距离才连接：

- Provider `TransferRange` 默认 **3 格**：`ExtensionCableProviderComponent.cs:15`
- Receiver `ReceptionRange` 默认 **3 格**：`ExtensionCableReceiverComponent.cs:22`
- 连接判定：欧氏距离 ≤ `min(provider.TransferRange, receiver.ReceptionRange)`，`ExtensionCableSystem.cs:147`
- 范围内取**最近**的 Provider（`ExtensionCableSystem.cs:262-284`）
- Guidebook 描述为「径向 2 格、四个正方向 3 格」（`VoltageNetworks.xml` zh-CN:34），与代码的欧氏 ≤3 格口径略有出入（见疑点 2）。

### 2.4 带电线缆电击伤害

`ElectrifiedComponent` 按电压分级伤害（`ElectrifiedComponent.cs:79-100`）：

| 电压 | 伤害倍率 | 电击时长倍率 |
|---|---|---|
| HV 高压 | ×3 | ×2 |
| MV 中压 | ×2 | ×1.5 |
| LV 低压 | ×1 | ×1 |

基础电击伤害 **7.5**（`ElectrifiedComponent.cs:100`），基础时长 5s（`:106`）。即裸手摸 HV 线 = 7.5×3 = 22.5 伤害；作业需绝缘手套（`VoltageNetworks.xml` zh-CN:88-93）。

## 3. 功率求解器（Pow3r）——每 tick 的电力结算

### 3.1 求解流程

`BatteryRampPegSolver.Tick()`（`BatteryRampPegSolver.cs:37-74`），每帧（PowerNetSystem.Update，`PowerNetSystem.cs:278-299`）执行：

1. `ClearLoadsAndSupplies`：清零所有负载实收功率与供应输出（`:76-94`）。
2. `GroupByNetworkDepth`：按电池跨网关系做**拓扑分层**（电池是唯一跨网设备，`:321-451`），同层网络可并行求解（`UpdateNetworkJob`，`:455-468`）。官方地图层数参考：Saltern `1477, 11, 2, 2, 3`、Box `3308, 20, 1, 5`（`:52-56` 注释）。
3. 每层并行 `UpdateNetwork`（核心算法，见 3.2）。
4. `ClearBatteries`：清理未参与本 tick 的电池标记（`:295-319`）。
5. `PowerSolverShared.UpdateRampPositions`：推进所有供应/电池的斜坡位置（`:5-86`）。

### 3.2 单网结算算法（UpdateNetwork，`BatteryRampPegSolver.cs:96-293`）

**① 汇总需求 demand**
- 负载：`demand += load.DesiredPower`（每个 PowerConsumer 的期望功率，`:104-114`）。
- 电池充电需求：`DesiredPower = min( MaxChargeRate + LoadingNetworkDemand / Efficiency , (Capacity - CurrentStorage) / Efficiency / frameTime )`（`:127-135`）——充电需求**与放电侧需求联动**（`LoadingNetworkDemand` = 上游 unmet），即电网缺电时电池更渴望充电。

**② 汇总本地供应 totalSupply**
- `effectiveSupply = min( SupplyRampPosition + SupplyRampTolerance , MaxSupply )`（`:149-150`）。
- `totalMaxSupply` 同时累计各供应的 `MaxSupply`（理论最大值，`:157`）。

**③ 缺口 unmet 与电池补缺**
- `unmet = max(0, demand - totalSupply)`（`:160`）。
- 仅当 unmet > 0 时电池才放电（**本地发电机优先于电池**，`:164-167` 注释）：
  `AvailableSupply = min( CurrentStorage / frameTime , min(MaxSupply, rampPos+Tolerance) + CurrentReceiving × Efficiency )`（`:180-188`）
  其中 `CurrentReceiving × Efficiency` 是「输入直通」项——**SMES 满电时充电电流可直接叠加到放电能力上**（直通机制，见 §6.3）。
- `MaxEffectiveSupply = min( CurrentStorage / frameTime , MaxSupply + CurrentReceiving × Efficiency )`（`:188`）。

**④ 按比例分配（限电核心）**
- `supplyRatio = min(demand, 总供应) / demand`（`:198-202`）。
- 每个负载：`ReceivingPower = DesiredPower × supplyRatio`（`:206-213`）——**全网所有设备按同一比例欠载**，即「限电（brownout）」：没有人被优先供电，也没有人被完全断电。
- 电池充电：`CurrentReceiving = DesiredPower × supplyRatio`；`CurrentStorage += frameTime × CurrentReceiving × Efficiency`（`:216-228`，并 clamp 到 Capacity）。

**⑤ 供应与电池出力**
- 发电机：`CurrentSupply = AvailableSupply × relativeSupplyOutput`；`SupplyRampTarget = MaxSupply × targetRelativeSupplyOutput`（`:231-252`）。
- 放电电池：`CurrentSupply = AvailableSupply × relativeBatteryOutput`；`CurrentStorage -= frameTime × CurrentSupply`（`:259-286`，clamp 到 0）。

**⑥ 斜坡推进（Ramping）**（`PowerSolverShared.cs:5-86`）
- 斜坡位置每帧向 `SupplyRampTarget` 移动 `±SupplyRampRate × frameTime`，clamp 到 `[0, MaxSupply]`（`:20-45`）。
- 这就是 Guidebook「功率爬升」条目的代码实体（`Ramping.xml` zh-CN）：**发电机/电池不会瞬时达到目标出力**，大负载突变必然短暂欠压。

### 3.3 默认斜坡参数（组件级，未覆写时生效）

| 参数 | Supply（发电机） | Battery（电池） |
|---|---|---|
| SupplyRampRate | 5000 W/s | 5000 W/s |
| SupplyRampTolerance | 5000 W | 5000 W |
| Efficiency | — | 1（100%，无损耗） |

（`PowerState.cs:356-357` Supply 默认；`PowerState.cs:421-424` Battery 默认。⚠️ 全库原型均未覆写 `efficiency`，见疑点 5。）

## 4. 设备接入组件体系

电网上的每种设备由若干组件组合而成（`BasePowerNet.cs:13-14`）：

| 角色 | 组件 | 作用 |
|---|---|---|
| 发电 | `PowerSupplierComponent` | 声明 MaxSupply / SupplyRampRate / SupplyRampTolerance（`PowerSupplierComponent.cs`） |
| 耗电 | `PowerConsumerComponent` | 声明 DesiredPower（需求），挂 HV/MV 网 |
| 储能 | `PowerNetworkBatteryComponent` + `BatteryChargerComponent` + `BatteryDischargerComponent` | 充电侧挂 `Network.BatteryLoads`、放电侧挂 `Network.BatterySupplies`（`PowerNet.cs:49-105`、`PowerNetSystem.cs:493-518`） |
| 低压受电 | `ApcPowerReceiverComponent` | 挂 APC 网；`Load = DesiredPower`，默认 **5W**（`ApcPowerReceiverComponent.cs:24-41`） |
| 低压供电 | `ApcPowerProviderComponent` + `ExtensionCableProviderComponent` | APC 输出侧与 LV 电缆 |

- **受电判定**：`IsPoweredCalculate` = 不需要电（NeedsPower=false）或实收功率≈需求功率（`PowerNetSystem.cs:324-330`）。
- **带内置电池的设备**（如手机、部分电脑）：断电时按 `IdleLoad`（默认 **5W**）消耗内置电池（`PowerNetSystem.cs:357-362`）；有电时充电，需求额外增加 `BatteryRechargeRate × BatteryRechargeEfficiency`（默认 **50W × 1**，`ApcPowerReceiverBatteryComponent.cs:27-42`，`PowerNetSystem.cs:364-368`）。
- **BatteryComponent ↔ PowerNetworkBattery 同步**：求解前 PreSync（容量/电量从 BatteryComponent 读入）、求解后 PostSync（写回），`BatterySystem.cs:48-76`、`PowerNetSystem.cs:285-291`。

| supplyRampTolerance | 1 000 W |
| supplyRampRate | **500 W/s**（三级电池中最慢） |

### 5.2 充电与放电

- **充电**：APC 的 input 节点（MVPower）作为 `BatteryCharger`（voltage: Medium，`apc.yml:144`）从 MV 网取电；求解器中充电需求 = min(5000 + unmet/Eff, 剩余空间/帧)（§3.2）。
- **放电**：output 节点（Apc 网）作为 `PowerProvider`；APC 电池被登记为 ApcNet 的 `BatterySupplies`（`PowerNetSystem.cs:485-490`），在 MV 供应不足时向整个 LV 网补电。
- **主断路器**：`MainBreakerEnabled` 默认 true（`ApcComponent.cs:27`）；切换断路器 = 切换 `battery.CanDischarge`（`ApcSystem.cs:137-138`）——⚠️ **断路器只关输出放电，不关输入充电**（疑点 6）。
- **电源优先级**：APC 总是先吃 MV 网本地供应（发电机→变电站），MV 缺额才由 APC 电池按比例补（§3.2-③）。因此「APC 满电但断电」通常意味着 MV/HV 上游断了，而 APC 电池正在为 LV 网放电。

### 5.3 过载跳闸

- `MaxLoad`（最大持续负载）= **20 kW**（`ApcComponent.cs:42`）。
- 当 `MainBreakerEnabled && CurrentSupply > MaxLoad` 持续 **3 秒**（`TripTime`，`ApcComponent.cs:48`）→ 自动跳闸（`TripFlag = true`，断路器断开）（`ApcSystem.cs:64-84`）。重新合闸会清除 TripFlag（`ApcSystem.cs:140-141`）。
- 目的：防止 APC 电池超载烧毁/快速耗尽。

### 5.4 状态显示与 EMP

- 电量状态：>90% 显示「满」（`HighPowerThreshold = 0.9f`，`ApcComponent.cs:34`）；否则按 供需差 判断 充电中/缺电（`ApcSystem.cs:220-232`）。
- 外部供电状态：Good / Low / None（`ApcSystem.cs:234-248`）。
- **EMP**：APC 受 EMP 脉冲会直接跳闸（`ApcSystem.cs:253-261`）。
- 电击：APC 通电时带电（`Electrified`，`apc.yml:169-175`）。
- 访问权限：工程（`AccessReader`，`apc.yml:30`）；可被 emag 撬开（`ApcSystem.cs:154-163`）。

### 6.2 接法

- 输入：`CableTerminalPortNode`（HVPower）——必须通过**电缆端子**（`CableTerminal`）接入 HV 输入网（`smes.yml:47-49`，`PowerStorage.xml` zh-CN）。
- 输出：`CableDeviceNode`（HVPower），设备底部直出 HV（`smes.yml:50-52`）。
- 端子隔离输入与输出网（`PowerStorage.xml` zh-CN「端子可确保 HV 输入与 HV 输出不会相连」）。
- 星光层：SMES 加装 `StationAiWhitelist`（`smes.yml:105`），精灵与音量有 `#SL` 改动（`:12-16, 146-147`）。

### 6.3 行为特性

- **充电**：HV 输入网有富余（demand < supply）时，SMES 按充电需求吸收功率（§3.2-①④）。
- **放电**：HV 网缺电时，SMES 作为 `BatterySupplies` 补缺（§3.2-③⑤），最大 150 kW、斜坡 1000 W/s。
- **直通（passthrough）**：电池满电时，输入电流经 `CurrentReceiving × Efficiency` 直接并入放电能力（`BatteryRampPegSolver.cs:183, 188`）——即「电池充满后，SMES 会将输入电力传递到输出」（`PowerStorage.xml` zh-CN）。这正是电池作为 HV 网之间「缓冲器」的核心机制。
- 充/放电状态判定：`CurrentSupply - CurrentReceiving` 正负（`SmesSystem.cs:70-81`）。
- 8MJ 满电以 150kW 全速放电可持续 8e6/1.5e5 ≈ **53 秒**；以 50kW 放电约 160 秒。

### 8.2 ⚠️ 电缆没有功率上限

求解器状态里**没有电缆节点**——只有 Supply/Load/Battery/Network（`PowerState.cs:20-23`），`PowerNet` 只聚合供应/负载/电池，**不存在每米电缆的额定功率**。与 SS13 不同，SS14 电缆不会因过载烧毁；功率上限只由 发电机/电池的 MaxSupply 与 APC 的 MaxLoad 决定（疑点 1）。

### 9.4 反物质引擎 AME（⚠️ 星光重写版）

星光对 AME 的注量/稳定性/功率代码做了整段重写，代码注释明确标注 `/* STARLIGHT taking control of AME injection Code */`（`AmeNodeGroup.cs:122-176`）。

- **功率公式**（`AmeNodeGroup.cs:189-199`）：
  `Power = max( 200000 × log10( 2 × 注量 × 核心数^(-0.5) ) , 0 )`（W）
  - 单核注量 2 → 200000×log10(4) ≈ **120.4 kW**（注释基准「120KW」`:191`）
  - 双核注量 4 → 200000×log10(2×4×2^-0.5) = 200000×log10(5.657) ≈ **150.5 kW**（注释「150kW」`:192`）
  - 双核注量 2 → 200000×log10(2×2×2^-0.5) = 200000×log10(2.828) ≈ **90.3 kW**（注释「90kW」`:192`）
  - 核心越多收益递减；18+ 核心注量 2 时结果 <0 被 clamp 为 0（`:197-199` 注释）。
- **安全注量**：`SafeFuelLimit = 核心数 × 2`（`AmeNodeGroup.cs:53`，`// STARLIGHT` 标记）。
- **稳定性（CoreIntegrity）**（`AmeNodeGroup.cs:134-176`）：
  - 注量 ≤ 安全值：每注量 `+ (SafeFuelLimit - 注量 + 1)`，上限 100——「在安全注量下稳定度缓慢回升」。
  - 注量 > 安全值（过载）：`-(注量 - 核心数)/核心数 - fuzz(-1..1)`，并触发管理员警报（当核心完整性跌破 95）。
- **注量调节**：默认 2（`AmeControllerComponent.cs:36`），步进 ±2（`AmeControllerSystem.cs:353-360`），上限 **核心数 × 8**（`:296-301`）。
- **核心判定**：盾体周围 8 格内 ≥8 个相邻盾 → 计为核心（`AmeNodeGroup.cs:72-80`）。
- **输出**：动态写入控制器 PowerSupplier 的 `MaxSupply`（`AmeControllerSystem.cs:106-109`；原型 `ame.yml:100-101` 的 supplyRate 为 0，运行时由代码覆盖）。

> 完整 AME 玩法见 `03-工程部/12-反物质引擎（AME）.md` 与 `65-奇点与特斯拉引擎机制百科.md`（AME 数值以本篇公式为准——星光已重写）。

## 10. 断电与负载处理全景

| 场景 | 系统行为 | 出处 |
|---|---|---|
| 供应充足 | 所有负载满额供电；电池（SMES 等）按剩余空间充电，`supplyRatio = 1` | `BatteryRampPegSolver.cs:198-213` |
| 轻度缺电（brownout） | 全网按 `supplyRatio < 1` **比例限电**：灯光变暗、机器减速但不断电；电池补缺 | `:202-213`；`Ramping.xml` zh-CN |
| 大负载接入/发电机掉线 | 发电机按斜坡爬升，期间持续欠压，数秒后恢复 | `PowerSolverShared.cs:5-45` |
| 电池耗尽 | 电池 `AvailableSupply` 归零，网络回到纯发电机供应；若仍不足继续比例限电 | `BatteryRampPegSolver.cs:180-188` |
| APC 输出过载 | 超 20 kW 持续 3 秒 → 跳闸，整个 LV 区域断电 | `ApcSystem.cs:64-84` |
| 设备自带电池 | 断电时用内置电池顶 IdleLoad（5W），来电后 50W 回充 | `PowerNetSystem.cs:348-368` |
| 充电优先级 | 无显式优先级——电池充电需求与普通负载**同池按比例分配**（代码 TODO 注释承认这点） | `BatteryRampPegSolver.cs:116-118` |

**开局供电**：班次开始时空间站完全靠电池（SMES 阵列）供电，「根据耗电量最多维持 5-10 分钟」（`Power.xml` zh-CN），随后需启动 AME/太阳能并逐步爬升到高级发电机。

## 14. 疑点清单

1. **电缆无额定功率**：求解器不建模电缆节点，HV/MV/LV 电缆均无功率上限，不会过载烧毁；网络唯一瓶颈是 电源 MaxSupply 与 APC MaxLoad（20 kW / 3 s 跳闸）。这是 SS14 与 SS13 电力系统的根本差异，Guidebook 也未提及。
2. **「电压网络」命名**：代码层只有 `NodeGroupID`（HVPower/MVPower/Apc）与 `Voltage` 枚举（`SharedPower.cs:38-43`），没有 VoltageNetwork 类；`VoltageNetwork` 是 Guidebook 条目 id。HV/MV 甚至共用同一个 `PowerNet` 类（`PowerNet.cs:24`）。
3. **LV 供电半径口径**：Guidebook 称「径向 2 格、正方向 3 格」（`VoltageNetworks.xml` zh-CN:34），代码是欧氏距离 ≤ min(3,3) = 3 格（`ExtensionCableSystem.cs:147`）——二者不等价（对角线距离 √8≈2.83 格内也可连）。
4. **APC 斜坡极慢**：APC 电池放电斜坡仅 500 W/s（`apc.yml:106`），比 SMES/变电站的 1000 慢一倍、比发电机（多数 500）相当——APC 电池补缺不是瞬时的，突然断电时 LV 设备会先经历限电再逐步恢复。
5. **电池效率恒为 1**：`PowerState.Battery.Efficiency` 默认 1（`PowerState.cs:424`），且全库原型（APC/SMES/变电站）均未覆写 `efficiency`——即充放电无能量损耗。若后续 fork 调整需注意该字段存在。
6. **APC 断路器只控放电**：主断路器切换仅改 `CanDischarge`（`ApcSystem.cs:137-138`），充电侧不受控——断路器关闭的 APC 仍会被 MV 网充电。
7. **AME 公式为星光重写**：`CalculatePower` 与稳定性逻辑整段标注 STARLIGHT（`AmeNodeGroup.cs:122-199`），与上游公式不同；文档数值不可与旧 Guidebook/上游资料混用。
8. **电池充电需求含下游缺口**：`DesiredPower = MaxChargeRate + LoadingNetworkDemand/Efficiency`（`BatteryRampPegSolver.cs:131`）——电网越缺电，SMES 越想充电，形成「抢电」正反馈；代码注释（`:116-118`）承认充电应后置处理但未实现。
9. **Ramping 示例的 100 kW 发电机**：Guidebook 示例（`Ramping.xml` zh-CN）泛指；实际爬升速率取决于各机型 supplyRampRate（500~7500 W/s），爬满 100 kW 需 13 秒（7500/s）~ 200 秒（500/s）。
10. **太阳能覆盖队列**：面板覆盖每 tick 只更新 1 块（`PowerSolarSystem.cs:102-107`），大阵列在太阳角度变化时存在最长 N tick 的更新滞后。
