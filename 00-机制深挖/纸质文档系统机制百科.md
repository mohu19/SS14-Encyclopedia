# 纸质文档系统机制百科

> 基线 commit：`7f25e682`（2026-07-26，zh-cn 分支）｜分析对象：STARLIGHT fork（SS14，C# + ECS + yaml）
> 源码层：`Content.Server/_Starlight/Paper/`（28 cs）+ `Content.Shared/_Starlight/Paper/`（6 cs）＝ **34 cs**（星光自研"签章动作"层）；另有官方 `Content.Shared/Paper/` 内的 Umbra/星光内联段（表单标签/签名/事件）

## 命名真相与范围

任务书问的"笔迹/装订/墨水"——**星光没有墨水消耗系统、没有装订机**（grep ink 在 `_Starlight/` 仅命中无关注释；装订类只有官方文件夹/剪贴板 + 星光新增的剪贴板变体）。星光 Paper 系统的**真正核心**是四件事：

1. **表单标签系统**（`[form]` / `[signature]` / `[datetime]` / `[check]`，盖章时自动定稿清理）——内联在官方 `PaperSystem.cs` 的 `#region Starlight`
2. **手写签名**（`Signature.ttf` 手写体字体 + "军衔 姓名, 职务"文字签名 + 可取消的 `PaperSignedEvent`）
3. **签章动作链**（`ActionsOnSign`：盖章/签名触发一连串 Action——发反派、加目标、加游戏规则、生成实体等，34 cs 的主体）
4. **文书实体体系**（文档打印机 51 种打印文书、21 种机密/简报文档、31 个印章、邮件反派招募信 7 种）

## 二、纸张基础与书写机制（官方层 + 星光内联）

### 2.1 书写

- 用**带 `Write` 标签的笔**点击纸张打开 UI 编辑（`PaperSystem.cs:182-188`）。写入有字数上限 `ContentSize`（普通纸默认 10000 字符，`PaperComponent.cs:15`；机密文档覆写为 12000）。
- 写入前触发 `PaperWriteAttemptEvent`（**星光新增**，`PaperSystem.cs:621`），可被取消并携带 `FailReason` 弹提示（:227-232）。
- **盖章后锁文**：纸上已有印章时不允许再编辑，除非使用的笔带 `WriteIgnoreStamps` 标签（`PaperSystem.cs:152-153`）。官方 CyberPen（`pen.yml:81`）与巫师笔（`pen.yml:148`）带此标签；星光的 `PenCyber` 赛博笔**不带**（仅 Write/Pen/CyberHandItem）。
- 写入后播放 `PaperScribbles` 音效（`PaperComponent.cs:33`）。

### 2.2 星光表单标签系统（核心自研，`PaperSystem.cs:461-605`）

文书正文支持 4 种标签，客户端渲染为交互元素（`Content.Client/Paper/UI/PaperWindow.xaml.cs`）：

| 标签 | 玩法效果 | 实现 |
|---|---|---|
| `[form]` | 点击弹**模态输入框**，玩家填内容替换标签（`PaperWindow.xaml.cs:396-414` OpenFormDialog） | 客户端替换后经 `OnSaved` 提交 |
| `[signature]` | 点击按钮 → 服务端用玩家**身份签名**替换：`军衔 姓名, 职务`（无军衔则降级组合，`PaperSystem.cs:488-537` GetPlayerSignature） | `PaperSignatureRequestMessage` → `ReplaceNthSignatureTag`（:542-563） |
| `[datetime]` | 点击 → 填入 `日期 // HH:MM Shift Time`（轮次内班次时长，:473-483） | `PaperDateTimeRequestMessage` → `ReplaceNthDateTimeTag`（:568-589） |
| `[check]` | 点击弹三选弹窗：☐ 空白 / ✔ 勾选 / ✖ 叉（`PaperWindow.xaml.cs:574-660`） | 客户端替换 `[check]` |

**盖章定稿**：任何印章盖到纸上时，`CleanUnfilledTags` 自动清理——删除未填的 `[form]`/`[signature]`/`[datetime]`，`[check]` 转成 ☐（`PaperSystem.cs:296-300` + :597-603）。即"盖章 = 表单定稿，没填的字段作废"。

实据：zh-CN 打印文书模板共 **351 处标签**（`Resources/Locale/zh-CN/_Starlight/paper/doc-printer.ftl`），如停尸房拒绝复苏报告含 `日期与时间：[datetime]`、`文件编制人：[signature]`、`姓名：[form]` 等（doc-printer.ftl:37、:768）。

### 2.3 手写签名（Umbra + 星光）

- 手里拿笔时 **alt+点击纸张** 出现"签名"动词（`PaperSystem.cs:318-340` AddSignVerb，需 `Write` 标签笔）。
- 签名 = 以玩家实体名 + 颜色 `#333333` + `StampType.Signature` + **星光手写字体** `/Fonts/_Starlight/Signature.ttf`（`🌟Starlight🌟` 标记，:346-352）盖一个通用印章图案，并写入 `StampedBy`。
- **星光改动**：`PaperSignedEvent` 被移入 `TrySign` 内、在真正盖章**之前**触发（:354-373 `// STARLIGHT START`），使事件可取消（`eve.Cancelled` → 拒绝签名并弹 `FailReason`）——**双用途**：既是"即将签名"通知，也是签名拦截点。
- 注意：**橡皮章盖章不触发 `PaperSignedEvent`**（盖章路径 :194-215 无事件），只有"签名"（TrySign）触发——所有 OnSign 系组件都挂在这个事件上。

## 四、签章动作链 ActionsOnSign（星光 Paper 层核心）

### 4.1 组件与流程

`ActionsOnSignComponent`（ActionsOnSignComponent.cs）：必填 `OnSignActionProto`（指向 `onSignActions` 原型）；`Instant`（默认 true，逐签即生效）；`Charges`（默认 1，签署次数）；`Signers`（已签者集合，防重复签）；`KeepFaxable`（admeme 逃生口，保留传真组件）。

流程（`ActionsOnSignSystem.cs:26-45`）：

1. 玩家**签名**（TrySign → `PaperSignedEvent`）时触发；`Charges <= 0` 或已签过 → 直接返回
2. 消耗 1 次 Charges、记录签名者
3. `Instant=true`：立即对**该签名者**执行动作列表
4. `Instant=false`：等到 **Charges 归零**才对**全体签名者**批量执行（"集齐 N 人再发动"）
5. 执行（:47-71）：按原型内顺序逐个 `Action`；`TargetsPaper=true` 的动作只对纸张本身执行一次；任一动作返回 `true` 即**中断**后续动作

**防滥用**：`MapInit` 时移除 `FaxableObjectComponent`（`ActionsOnSignSystem.cs:19-24`，注释 "cause this breaks shit like infinite antags"）——传真机复印会复制出无限份可签文书，直接摘掉传真能力（KeepFaxable 例外）。邮件信描述"Wont fit in a fax somehow"即此机制的口径。

## 九、疑点清单

1. **Multistamp 移除逻辑反直觉**（`SharedMultistampSystem.cs:49`）：`CurrentEntry = !(Count > CurrentEntry) ? CurrentEntry : 0`——当前索引仍有效时被重置为 0，索引越界时反而保留旧值（随后 SetMultistamp 显示 "no-behavior"）。疑似条件写反，但表现上"删到空显示无行为"恰好成立，未修。
2. **概率判定在消耗次数之后**（AntagOnSignSystem.cs:54-58、ObjectiveOnSignSystem.cs:48-52）：签名先扣次数再 roll，**抽奖失败也烧掉一次机会**，且已签者永远不能再签（SignedEntityUids）——信纸是一次性消耗品，运气差直接报废。
3. **传真防御一刀切**：三个 OnSign 系组件 MapInit 都 `RemComp<FaxableObjectComponent>`（注释 "breaks shit like infinite antags"）。若玩家先用传真机复印再签名，复印件**没有** FaxableObject 组件但 OnSign 组件还在——复印件仍可签（签章动作照常触发），只是不能再传真。KeepFaxable 仅 admeme 原型可用。
4. **地狱契约正则语言断层**（`Devil/contract.yml:25`）：必填正则要求正文**逐字**含英文条款且含 `[bold]` 标记字面量（`(?<=I understand that ... \[bold\]I understand ... \[/bold\]).*`）；若契约正文模板走 zh-CN 本地化（中文填写），`IsPaperValid` 必然失败无法签署——需手写英文原文。与恶魔篇结论一致。
5. **AdjustChargesPopBased 一次性快照**（AdjustChargesPopBasedSystem.cs:16-21）：只在 MapInit 按当时在线人数算次数，后续人口增减不重算——开局 65% 人口签名的门槛在回合中段可能过松/过紧。
6. **GameruleOnSignSystem 文件名拼写错误**：`GameruleOnSignSytem.cs`（Sytem），类名本身正确，不影响运行，属代码卫生问题。
7. **"Q 的终结"纸是幽灵角色**（events.yml:100-125）：BasePaperQuietChaos 带 GhostRole + 语言 + TTS + 变形组件——文书系统里混入了"可附身的混沌纸"这种反派玩法实体，与普通文书流程无关，属于管理员事件用品。
8. **盖章定稿清理的副作用**（PaperSystem.cs:296-300）：`CleanUnfilledTags` 会把**所有** `[check]` 转成 ☐、删掉**所有**未填标签——盖章后表单无法再补填（编辑也被锁），"漏填即作废"是设计意图，但同一张纸多处 `[signature]` 只填一处、其余签名位盖章后直接消失，玩家可能误以为被吞字。
9. **机密文档只读但可被签名**：`ImportantDocumentGeneric` 禁编辑（editingDisabled）但仍可盖印/签名（StampedBy 无限制）——"只读"指内容不可改，签章链照常可挂（若管理员给机密文档挂 OnSign 组件即可触发，yaml 目前没有）。
10. **文本文件内容不可见**：`/Documents/<locale>/` 的 txt 未被稀疏克隆拉取（资源目录），机制可推断但无法核对正文是否含标签/英文（zh-CN 文档正文在 ftl 有中文模板，但 TextFilePaperContent 走的是 txt 文件，二者可能并存两套内容）。
