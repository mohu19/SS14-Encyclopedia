## 一、总览

科技树（Research）是科研部（R&D）的核心经济系统：**服务器聚合研究点 → 控制台消耗点数解锁科技节点 → 节点解锁车床配方/特殊效果**。全库共 **96 个科技节点原型**（官方层 55 + 星光层 39 + FarHorizons 层 2），按 **5 大学科** 组织（星光新增第 5 学科"生物化学"），分 1-4 层（Tier）。星光实际活跃层 **94 节点**，全部节点总成本 **817,620 研究点**（不含隐藏战利品科技与 FarHorizons 层；含两者为 837,620 / 30,837,617）。

系统为经典 SS14 架构：**yaml 原型定义数据（节点/学科/配方），C# ECS System 执行逻辑**。核心类为 `ResearchSystem`（Server 侧 partial 类群）+ `SharedResearchSystem`（共享层，卡片/层级/主学科逻辑）。

### 3.2 层级解锁算法（`SharedResearchSystem.GetHighestDisciplineTier`）

`Content.Shared/Research/Systems/SharedResearchSystem.cs:110-155`，逻辑：

1. Tier 1 永远可用（`var tier = 2; //tier 1 is always given`，:129）
2. 进入 Tier N 需：Tier N-1 的**已解锁科技数 / 该学科 Tier N-1 总科技数 ≥ tierPrerequisites[N]**（= 75%）
3. 主学科锁定检查：`tier >= lockoutTier(4) && MainDiscipline != null && 本学科 != MainDiscipline` → 中断
4. 返回 `tier - 1`（最高可达层级）

伪代码：

```
tier = 2
while tier <= maxTier:
    if 已解锁(Tier tier-1 科技) / 总数(Tier tier-1 科技) < 0.75: break
    if tier >= 4 and 已有主学科 and 本学科 != 主学科: break
    tier++
return tier - 1
```

### 3.3 主学科锁定（lockout）

- 解锁任意 **Tier ≥ 4** 的科技时，`TrySetMainDiscipline` 把该科技所属学科设为 `MainDiscipline`（`SharedResearchSystem.cs:228-241`，判定 `prototype.Tier < discipline.LockoutTier` 则跳过）。
- 一旦主学科确立，**其他学科的最高可达层级被锁死在 Tier 3**（见 3.2 第 3 步）；主学科自身可继续研究 T4。
- 全库仅 3 个 T4 科技：反克隆技术、扫描门技术（军备）、暗物质破障器（实验）——即"点出任意 T4 = 全站科研路线定型"。
- 数据库脱离服务器时清空主学科（`ResearchSystem.Technology.cs:161-171` OnDatabaseRegistrationChanged）。

### 3.4 科技卡片机制（+ 星光防重roll补丁）

- 服务器数据库维护 `CurrentTechnologyCards`：`UpdateTechnologyCards` 把当前全部"可用科技"洗牌，**每个受支持学科抽 1 张**作为候选卡片（`SharedResearchSystem.cs:38-56`）；客户端控制台 UI 以卡片形式展示（`Content.Client/Research/UI/ResearchConsoleMenu.cs:73`）。
- 可用性判定 `IsTechnologyAvailable`（`SharedResearchSystem.cs:74-97`）：非隐藏 且 学科受支持 且 层级 ≤ 当前可达层级 且 未解锁 且 前置全部已解锁。
- **星光防重roll补丁**（`SharedResearchSystem.cs:25-33`，`// Starlight BEGIN/END`）：`OnMapInit` 时若实体带 `ResearchClientComponent`（如 R&D 控制台），**跳过本地卡片生成**——卡片改由服务器同步而来，杜绝"拆机重造刷新卡片"的上游漏洞。源码注释明言此动机。

## 四、研究点（Research Points）获取与流转

### 4.1 服务器聚合模型

- 核心数据：`ResearchServerComponent`（`Content.Shared/Research/Components/ResearchServerComponent.cs`）——`Points`（点数）、`ServerName`（默认 "RDSERVER"）、`Id`（自增唯一，`ResearchSystem.Server.cs:16-22`）、`Clients`（已注册客户端列表）、`ResearchConsoleUpdateTime`（默认 **1 秒**，:44）。
- 结算循环：`ResearchSystem.Update` 每 1 秒对每个服务器执行 `UpdateServer`（`ResearchSystem.cs:91-102`）：`Points += GetPointsPerSecond(server) × 1s`，前提是服务器有电（`CanRun`，`ResearchSystem.Server.cs:40-53`）。
- **点源注册模型（关键）**：服务器不直接持有产点组件。它向每个客户端 Raise `ResearchServerGetPointsPerSecondEvent`，由**挂载在客户端（或服务器本体）上的点源组件**响应并累加 `args.Points`（`ResearchSystem.Server.cs:133-149`）。服务器在网格内发现客户端（同 grid，`ResearchSystem.cs:80-89`），客户端开机/锚定自动注册第一个服务器（`ResearchSystem.Client.cs:64-68, 80-94`）。
- 注册/注销同步数据库：`Sync` 把服务器数据库整体复制给客户端（`ResearchSystem.Technology.cs:14-29`）。

### 4.2 产点途径①：R&D 点源组件

- `ResearchPointSourceComponent`：`pointspersecond` + `active` 两字段（`Content.Server/Research/Components/ResearchPointSourceComponent.cs:6-10`）。
- 产点条件：`Active && 有电`（`ResearchSystem.PointSource.cs:20-23`）。
- 全库唯一定义：`BaseResearchAndDevelopmentPointSource` 基实体，**25 点/秒**（`Entities/Structures/Machines/research.yml:109-111`）；文件头注释直言"等有实际点源后应改为 abstract"——目前无任何具体点源子类。

### 4.3 产点途径②：异常容器（Anomaly Vessel）

- 容器挂载异常后每秒产点：`args.Points += (int)(GetAnomalyPointValue(anomaly) × PointMultiplier)`（`Content.Server/Anomaly/AnomalySystem.Vessel.cs:73-79`）；实验容器 `pointMultiplier: 2`（`Entities/Structures/Machines/anomaly_equipment.yml:103`）。
- 单异常点值公式（`Content.Server/Anomaly/AnomalySystem.cs:182-205`）：

```
points/s = (Max − Min) × sigmoid(7 × (Severity − 0.5)) × multiplier + Min
multiplier = 1.5（Stability > GrowthThreshold 时，GrowingPointMultiplier）
           × (1.5^Health − 0.5)        # 健康惩罚，最多 −50%
           × behavior.EarnPointModifier # 异常行为加权
```

- 组件默认：`MinPointsPerSecond = 10`、`MaxPointsPerSecond = 70`、`GrowingPointMultiplier = 1.5f`（`Content.Shared/Anomaly/Components/AnomalyComponent.cs:244/251/258`）。
- ⚠️ 星光新异常**香蕉/小丑异常 `min/max = 0`，不产研究点**（`_Starlight/Entities/Structures/Specific/Anomaly/anomalies.yml:169-170`；普通异常 466-467 行仍为 10/70）。

### 4.4 产点途径③：零空间汲取器（星光自研）

- 穿戴物 `ClothingNullSpaceDrainer`（"零空间汲取器"，`_Starlight/Entities/Clothing/Back/misc.yml:3-30`）：**100 点/秒**（`Content.Server/_Starlight/NullSpace/NullSpaceDrainerComponent.cs` `Points = 100`）。
- 机制：佩戴者须为**影裔（Brighteye，明眼能量 > 0）**，每秒消耗其明眼能量 **1** 换 100 研究点（`NullSpaceDrainerSystem.cs:44-53`，代码注释 "You fucking monster... coding this makes me sad for my kins."）。
- 其余特性：`IdClothingBlocker` 限制安保/见习/指挥可用；自带 `ResearchClient`，可手持打开服务器选择 UI 注册产点。
- ⚠️ 组件定义在 **Server 层**（`Content.Server/_Starlight/NullSpace/`），与惯例（共享层）不同。

### 4.5 产点途径④：文物分析仪提取（一次性）

- 分析控制台点"提取"按钮：把文物**所有节点**的剩余研究值一次性转入服务器（`Content.Server/Xenoarchaeology/Equipment/ArtifactAnalyzerSystem.cs:30-50`）；`sumResearch <= 0` 不转（注释 "It's a sad day when a scientist makes negative 5k research"）。
- 单节点研究值公式（`Content.Shared/Xenoarchaeology/Artifact/SharedXenoArtifactSystem.Node.cs:375-394`）：

```
ResearchValue = int( 1.25^(前置节点数^1.5) × BasePointValue × durabilityMultiplier )
durabilityMultiplier = 活跃节点 1 + (耐久/最大耐久)² ；非活跃节点 1 − (耐久/最大耐久)²
```

- `BasePointValue` 默认 **4000**（`Content.Shared/Xenoarchaeology/Artifact/Components/XenoArtifactNodeComponent.cs:67`）。
- 每节点只能提取一次（`ConsumedResearchValue` 累计，`GetResearchValue = max(0, ResearchValue − Consumed)`，Node.cs:154-160）。

### 4.6 研究点磁盘（Research Disk）

- 实体：`ResearchDisk`（1000 点）/ `ResearchDisk5000` / `ResearchDisk10000`（`Entities/Objects/Specific/Research/disk.yml:1-42`）；插入服务器即加点数并销毁（`Content.Server/Research/Disk/ResearchDiskSystem.cs:23-35`）。
- 调试盘 `ResearchDiskDebug`（`unlockAllTech: true`）：MapInit 时 `Points = 全部科技成本之和`（`ResearchDiskSystem.cs:37-44`），即一次性点满全树。
- 磁盘也可作为忍者偷盗目标（`StealTarget`，disk.yml:63-64）。

### 4.7 点数消费

- 解锁科技：`ModifyServerPoints(server, −cost)`（§5.1）。
- 打印科技磁盘：`−1000` 点/张（§6.3）。
- 点数不存在负值保护之外的检查：`CanServerUnlockTechnology` 校验 `cost <= server.Points`（`ResearchSystem.Technology.cs:155-156`）。

## 五、解锁流程与广播

### 5.1 控制台解锁管线

R&D 控制台实体 `ComputerResearchAndDevelopment`（`Entities/Structures/Machines/Computers/computers.yml:587-634`）：`ResearchClient + ResearchConsole + TechnologyDatabase`，**需"科研"（Research）权限**（:624-625），耗电 **1000 W**（:620-621）。

解锁消息处理（`Content.Server/Research/Systems/ResearchSystem.Console.cs:34-88`）：

1. 控制台须有电；原型须存在
2. 权限校验：`AccessReader` 不通过 → 弹"无权限"提示（:44-48）
3. `UnlockTechnology`（`ResearchSystem.Technology.cs:68-91`）：可用性检查 + 点数足够 → `AddTechnology`（服务器数据库加科技+配方，:110-133）→ `TrySetMainDiscipline` → **扣点** → `UpdateTechnologyCards` 刷新卡片 → 写管理员日志
4. **广播**：默认频道 `AnnouncementChannel = "Science"`（`Content.Server/Research/Components/ResearchConsoleComponent.cs:13`）+ 该科技 `radioChannels` 列出的附加频道（如 Security/Supply/Engineering/Service/Medical/Binary/Command），消息含科技名/花费/操作者身份（:58-74）
5. **emag 静默**：控制台被电磁卡（EmagType.Interaction）后解锁不广播（:139-148，`GotEmaggedEvent` 处理器）

### 5.2 星光成就

解锁使服务器卡片清空（`CurrentTechnologyCards.Count == 0`，即该服务器科技全解锁）时，给所属站点的**科研总监（ResearchDirector）岗位**发放 `theory_of_everything` 成就（`ResearchSystem.Console.cs:76-85`，`// Starlight start: Achievements`）。

## 十、疑点清单

1. **FarHorizons 核能双科技是否星光可玩**：`_FarHorizons/Research/industrial.yml` 的 NuclearPowerGeneration/Recycling 定义存在且工业学科加载，但该 fork 层主要为 IPC 玩法，实际是否进游戏预设/地图未验证（sparse 克隆无 Maps）——按"定义存在 ≠ 玩家可玩"标注。
2. **lootonly 隐藏科技成本 9999999**：设计意图为"只入战利品池"（文件头注释自证），隐藏科技被 `IsTechnologyAvailable` 一刀切拒绝（SharedResearchSystem.cs:78-79），但科技磁盘抽取配方不排除隐藏——两处语义需配合理解。
3. **零空间汲取器组件位于 Server 层**（`Content.Server/_Starlight/NullSpace/NullSpaceDrainerComponent.cs`），违反"组件在共享层"惯例；且其产点依赖影裔明眼能量（跨系统耦合，影裔篇见 `00-机制深挖/影裔机制数值百科.md`）。
4. **基础 R&D 点源无具体子类**：`BaseResearchAndDevelopmentPointSource` 注释自认"等有实际点源后应改 abstract"（research.yml:99），目前 25/s 是唯一 ResearchPointSource 定义。
5. **星光新异常不产点**：香蕉/小丑异常 `min/max 0`（anomalies.yml:169-170），装进容器是零收益（或纯装饰/实验行为）。
6. **官方配方列表含重复 ID**：DraconicMunitions/UraniumMunitions 各含重复的 `MagazinePistolSubMachineGun*Incendiary/Uranium`（arsenal.yml:46/116）、BasicShuttleArmament 含重复 `MagazineGrenadeEmpty`（:245）——列表不去重，但 `AddTechnology` 用 Contains 去重，无实际影响。
7. **Guidebook 中文条目是空壳**：`06-科学部/08-科技.md`（Technologies）仅含 5 个章节标题，且章节名（军械库/生化）与 zh-CN locale 官方译名（军备/生物化学）不一致；本篇以 locale 译名为准。
8. **磁盘终端价格走组件默认**：`DiskConsoleComponent.PricePerDisk = 1000`（DiskConsoleComponent.cs:14），实体 yaml 未覆写——若未来调价需改组件默认或实体覆写。
9. **主学科锁定的"第一次"竞态**：T4 科技解锁瞬间即锁定主学科（TrySetMainDiscipline），之后其他学科 T3 封顶；反克隆（30000 点）与暗物质破障器（30000 点）是仅有的两个"高成本 T4"，扫描门仅 5000 点——先点扫描门即可低成本锁路线（疑似平衡隐患，未验证）。
10. **蓝图与科技树并行**：蓝图（§6.2）与科技磁盘（§6.3）都绕过研究点成本直接给配方——蓝图不可研究获得（仅地图/事件投放），与 lootonly 同理。
