### 1.2 目标抽取与难度预算

- **固定目标**：`AntagObjectives` 组件直接列目标 id（恶魔/SELF/终结者/绑架者/明眼/邪教/异形克隆，如 `subgamemodes.yml:5-10`）。

- 权重组：`weightedRandom` 原型（`objectiveGroups.yml`），组内权重见下表。

## 2. 反派生成规则（GameTicking）

### 2.1 架构与生成方式

规则 = `- type: entity` 的 GameRule 原型（`BaseGameRule` 父类）+ 组件组合，System 处理行为。星光反派登场四通道：

| 通道 | 机制 | 代表 |
|---|---|---|
| 开局选人 | `selectionTime: IntraPlayerSpawn`（按偏好） | 叛徒/小偷/吸血鬼/变形怪/SELF/恶魔 |
| 出生前 | `PrePlayerSpawn` | 异形机械体（SubXenoborgs）/明眼 |
| 中局事件 | `StationEvent` + `AntagSpawner`/幽灵点 | 绑架者/终结者/恐怖蜘蛛/明眼/异形克隆 |
| 动态规则 | `DynamicRule` 预算表（SLDynamicRule） | 主/小/多反派/中局全池 |

### 2.2 选人语义（写条目必用）

- `pickPlayer: false` = **幽灵抢答制**（raffle，终结者/恐怖女皇/绑架者/异形机械体/异形克隆）。
- `playerRatio: N` = 每 N 个玩家 1 个名额；`min`/`max` 硬上下限。
- 角色时长门槛（`Roles/Antags/*.yml` requirements，antag-system-map 已验）：终结者 5h、恐怖女皇 48h、SELF 特工 24h+博格 6h+科学家 5h+机器人专家 5h、恶魔 10h 且非 IPC、孤独绑架者 安保 3h+外科 3h。

## 3. 回合流程（GameTicking 星光改动）

### 3.1 GameTicker 核心改动

- **核弹结束回合**（`Content.Server/GameTicking/GameTicker.cs:147-162`，`#region Starlight`）：非核战局（无活跃 Nukeops 规则）核弹爆炸 `EndRound()`；核战局由核战规则系统自己处理。CVar `game.nuke_round_restart_time` 默认 **20s**（`StarlightCCVars.Game.cs`）——核弹后回合结束倒计时。
- RoundFlow 星光改动：移除开局随机人形档案生成（:397）、地图/玩家挂载规则分开启动（:428,432）、回合重启时 BugReport 管理器重启（:735）。
- **Discord 状态推送**（`GameTicker.Starlight.cs:128-211`）：每秒向 webhook 推送玩家数/地图/模式/回合时长/PanicBunker（staff webhook 另带在线管理员/导师数）；模式名可被 CVar `OverrideGamemodeName/Description` 覆盖。

### 3.2 回合结束投票（RoundEndVoteSystem，`GameTicker.RoundEndVote.cs`）

- 投票触发：`RoundEndSystemChangedEvent`（回合结束流程启动）且玩家数 ≥ `vote.min_player_to_vote`（默认 **2**，`StarlightCCVars.Vote.cs:9-10`）。
- 投票时间 = `LobbyDuration - 90s`（`vote.votings_delay` 默认 90，:27-28）。
- `vote.run_map_vote_after_restart` / `vote.run_preset_vote_after_restart` 默认 **false**（:21-25）；`game.reset_preset_after_restart` 为真时开局自动切回 **Secret**（:42-43，`GameTicker.RoundEndVote.cs:40-41`）。

### 3.3 大厅内容与简报

## 4. 疑点清单

1. **BloodDranked 死字段**：`BloodDrainConditionComponent.BloodDranked`（`BloodDrainCondition.cs:9`）全库**无任何写入方**，吸血进度实际用 `vampComp.TotalBlood / target`（`VampireSystem.cs:823`）——即"总血量"而非"本局吸了多少"。
2. **明眼能量硬编码**：`events.yml:149` `energy: 200`，注释原文 "THIS IS HARDCODED BULLSHIT... i wish i could set this auto to MaxEnergy"。
3. **恐怖蜘蛛进化目标区间 0-99**（`terror_spider.yml:18-20`）：NumberObjective 的 min/max 是**随机抽取区间**，进化目标可能抽出 0——与"必须进化"的设计意图矛盾（需确认 EvolveCondition 是否另有限制）。
4. **Dynamic 预设玩家不可投票**：官方 `game_presets.yml:140` 注释 "admin-only for now until we fix some bugs"（showInVote false）；Secret 预设的规则列表**不含** SLDynamicRule（:150-158），Secret 是否经 SecretRuleSystem 的权重表间接选中 Dynamic 未验证。
5. **Deathmatch 预设限制全注释**：官方 `game_presets.yml:181-187` 的 minPlayers/maxPlayers/showInVote/supportedMaps 被星光整段注释，Deathmatch31 可直接使用（疑似测试残留）。
6. **部门目标与任务卡**：`DepartmentObjectiveSystem.cs:26` 任务卡完成查询恒 true——部门目标挂卡后**不提供真实完成判定**，只贡献标题与进度显示。
7. **Traitor 预设 minPlayers 0 + showInVote true**（`game_presets.yml:167,170`，🌟Starlight🌟 标记）：叛徒局无人数门槛。
8. **吸血鬼血仆目标** `VampireThrallObeyMasterObjective` 难度 0.1 且 FreeObjective，无任何进度系统——纯 RP 目标。
9. **绑架者目标共享**：`AbductorSystem.Console.cs:68-79` 通过遍历所有 mind 找对方的 AbductCondition——若同局多名绑架者，进度互相计入（设计如此但无显式配对）。
