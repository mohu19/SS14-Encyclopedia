## 一、总览：蓝空间 ≠ 单一系统，是"科技主题 × 多机制"的复合层

蓝空间在星光 fork 中没有统一的大 System，而是**一套科技主题下的分散机制**，按实现形态可分四块：

| 板块 | 实现形态 | 核心代码 |
|---|---|---|
| 蓝水晶物品本体 | 星光 C# 系统（2 cs）+ yaml | `Content.Server/_Starlight/Bluespace/`（78 行 + 32 行） |
| 蓝空间收割机 | 星光 C# 系统（Server 1 + Shared 4）+ yaml 池原型 | `Content.Server/_Starlight/Power/EntitySystems/BluespaceHarvesterSystem.cs`（344 行） |
| 蓝空间植入体/传送设备 | 纯 yaml（官方组件组合：TriggerOnMobstateChange/DeleteOnTrigger/SpawnOnTrigger） | `_Starlight/Entities/Objects/Misc/subdermal_implants.yml` 等，**无专属 C# 系统** |
| 低温传送 | 星光 C# 主系统 + 官方 CryostorageSystem 内嵌星光段 + 星光归属系统 | `Content.Server/_Starlight/CryoTeleportation/CryoTeleportationSystem.cs`（184 行） |

判定：**蓝水晶有独立 C# 系统（BluespaceCrystalSystem），但蓝空间整体不是单一系统**——收割机/植入体/低温传送各自独立，yaml 数据占比很高。本文按"科技主题"串讲。

C# 全库 bluespace 关键字命中 14 个文件（`Content.Server/_Starlight/` 8 + `Content.Shared/_Starlight/` 6），其中与影裔/邪教/心灵尖啸的交叉命中（CosmicBlankSystem、PsychicScreachRule、NullSpaceSystem、ShadekinSystem）属零空间驱逐联动，见第七节。

## 三、蓝空间科技应用（除收割机外）

### 3.1 蓝空间植入体（Bluespace Implant / Redspace Implant）

纯 yaml 机制——**无专属 C# 系统**，由官方组件组合实现（`_Starlight/Entities/Objects/Misc/subdermal_implants.yml:60-77`）：

```
BluespaceImplant（永久植入，HideSpawnMenu）
├─ TriggerOnMobstateChange: Dead   → 死亡时触发
├─ TriggerOnActivateImplant        → 手动激活也可触发
├─ DeleteOnTrigger: targetUser     → 触发后删除使用者身体
└─ SpawnOnTrigger: BluespaceImplantEffect → 生成蓝空间传送门特效
```

## 四、蓝空间收割机（Bluespace Harvester）—— 电力 → 独立点数 → 兑换

### 4.1 定位（重要！）

**收割机把电力转换成独立的"收割机点数"池，点数用于兑换配置好的战利品池——不是研究点，与科技树完全无关**（`BluespaceHarvesterSystem.cs:18-21` 注释原文："convert electrical power into OWN research points. Points can be spent to spawn items from configurable loot pools"——注意注释说 research points 但实际是独立点数池，代码里 Points 字段独立于科技树研究点）。

### 4.2 实体与建造

- 实体：`BluespaceHarvester`，BaseMachine，HV 供电（PowerConsumer voltage: High / CableDeviceNode HVPower），耐久 **600**（DamageTrigger 600 → Destruction，bluespace_harvester.yml:68-75），电网监控组 Generator（collectionName bluespaceHarvester）
- 电路板 `BluespaceHarvesterMachineCircuitboard`：**机械臂 3 / 钢 5 / 电缆 5 / 蓝水晶 2**（power.yml:8-16）
- 界面：ActivatableUI（需供电）+ BluespaceHarvesterBoundUserInterface；中文 UI 文案全量存在（`Locale/zh-CN/_Starlight/ui/bluespace-harvester.ftl`，含「蓝空间收割机」「输入等级/目标等级/当前功耗/电网供电」等）

### 4.3 等级与点数（核心数值）

**10 级功耗表**（`BluespaceHarvesterComponent.cs:15-27`，实体 yaml 未覆写，C# 默认即真值）：

| 等级 | 功耗（W） | 等级 | 功耗（W） |
|---|---|---|---|
| 1 | 1,000（1kW） | 6 | 1,000,000（1MW） |
| 2 | 5,000（5kW） | 7 | 5,000,000（5MW） |
| 3 | 50,000（50kW） | 8 | 10,000,000（10MW） |
| 4 | 100,000（100kW） | 9 | 25,000,000（25MW） |
| 5 | 500,000（500kW） | 10 | 100,000,000（100MW） |

**点数生成公式**（BluespaceHarvesterSystem.cs:156-157）：

```
每秒点数 = PointsPerLevel(2) × 当前等级 + PointsPerMegawatt(8) × (实际供电 / 1,000,000)
```

- PointsPerLevel = **2** / PointsPerMegawatt = **8**（Component.cs:29,31）
- 小数累计器（accumulator）：整点才入账，不丢小数（:159-168）
- 实际等级 = 供电能支撑的最高等级（逐级比较，含 0.01W 容差 epsilon；不超过目标等级，System.cs:247-264）；目标等级由 UI 设置，DrawRate = 目标等级功耗（:275-285）
- **每 1 秒**结算一次（UpdateDelay = 1s，Component.cs:10）

## 五、低温传送（CryoTeleportation）—— 离线/离身玩家身体自动送低温舱

### 5.1 机制定位

星光自研的**玩家身体管理机制**：玩家断线、或离开身体（幽灵/换身）后，其身体在站内逗留超过 **7 分钟**，就会被自动传送到空闲的低温睡眠单元（cryo storage）保存——身体不留在现场，职位槽位释放给后来者。配套系统把原玩家的随身物品打包，交给接手该职位的晚进玩家。

### 5.2 组件链

| 组件 | 挂载 | 关键字段 | 出处 |
|---|---|---|---|
| `StationCryoTeleportationComponent`（站级开关） | 站实体（抽象基类 `BaseStationCryoTeleportation` 挂在官方 NanotrasenStation + NanotrasenCentralCommand，`#Starlight` 标记） | **TransferDelay = 420s（7 分钟）**；PortalPrototype = "CryoPortal"；传送音 teleport_departure.ogg | StationCryoTeleportationComponent.cs:10-16；`_Starlight/Entities/Stations/base.yml:1-5`；官方 `nanotrasen.yml:30,42` |
| `TargetCryoTeleportationComponent`（个体标记） | 玩家出生时挂载（OnCompleteSpawn） | Station（所属站）/ ExitTime（离身时刻）/ UserId / **TimeDelay = 0**（额外宽限，默认 0） | TargetCryoTeleportationComponent.cs:12-27；CryoTeleportationSystem.cs:96-107 |
| CVar `game.cryo_teleportation` | 服务器 | **默认 true**（SERVERONLY）；为 false 时出生不挂组件，机制整体关闭 | StarlightCCVars.Game.cs:16-17 |

### 5.3 触发条件（Update 每 5 秒轮询，全部满足才传送）

CryoTeleportationSystem.cs:55-67 的完整条件链（任一不满足即跳过）：

1. 组件 `Station` 非空
2. 所属站有 `StationCryoTeleportationComponent`
3. 所属站有 `StationDataComponent`
4. **不是博格**（无 BorgChassisComponent）
5. **存活**（MobState.Alive）
6. `ExitTime` 非空（玩家已离身/断线）
7. 离身时长（`CurTime - ExitTime - TimeDelay`）**≥ 420s**
8. 不在低温容器中（无 CryostorageContainedComponent）
9. **无 `UncryoableComponent`**（官方组件：不可低温者，如 AI）

轮询节拍：`_refreshCooldown = 5s`（:38），计时器累积（:37,50-53）。

**ExitTime 的写入/清除**（谁算"离身"）：
- 玩家脱离身体（PlayerDetachedEvent）且身体存活 → 记录时刻（:109-118）
- 玩家重新附身（PlayerAttachedEvent）→ 清除（:120-126）
- 会话断线（SessionStatus.Disconnected）→ 记录；重连（Connected）→ 清除（:128-139）
- 断线离身期间顺带记录 UserId（供后续职位/归属处理）

### 5.4 传送流程

```
满足全部条件
├─ 找站内主网格上的空闲低温单元（FindCryoStorage，:150-183）：
│    只扫 MainGrids（主网格为空才回退全部 Grids）→ 排除 ATS/穿梭机上低温单元
│    容器 "storage" 必须为空（CryostorageComponent + TransformComponent 查询）
│    找不到 → 本次放弃，下轮再试
├─ 玩家当前位置生成 CryoPortal 传送门（2s 蓝色门，半径 3 光源，teleportation.yml:39-62）+ 传送音
└─ 塞入低温单元容器 + HandleEnterCryostorage（官方系统，见 5.5）
```

### 5.5 官方 CryostorageSystem 承接行为（含星光内嵌改动）

进入低温舱后（`Content.Server/Bed/Cryostorage/CryostorageSystem.cs:174-230+`）：

- **职位槽位全部归还**（玩家持有的所有站内职位 +1 槽位，然后移除玩家职位记录）
- **星光内嵌段**（`// Starlight start/end`）：每个归还职位触发 `CryoSlotReturnedEvent`（见 5.6）；移除身体的 **HeadRevolutionary（头部革命者）与 CommandStaff（指挥层）组件**
- 身体移入**暂停地图**（PausedMap，低温睡眠地图，不参与模拟）
- 播放移除音、全站公告「earlyleave-cryo-announcement」（角色名/职位）
- 删除站内档案记录；玩家保留 mind（可随时回来取回身体）

**低温睡眠单元**（官方实体 `Entities/Structures/cryogenic_sleep_unit.yml`）：Cryogenics 访问权限（AccessReader）、拖拽放入 2s（DragInsertContainer entryDelay 2）、移动即退出（ExitContainerOnMove）、绿灯光源。

## 九、疑点清单

1. **PortalBlockDuration = 30f 是死字段**：`BluespaceHarvesterComponent.cs:57` 定义了"裂隙封锁时长 30s"，但 `BluespaceHarvesterSystem` 全文件无一处读取——实际解锁由裂隙实体 `TimedDespawn 30s`（hellport.yml:19）+ `ComponentShutdown`（System.cs:108-119）驱动，两者恰好都是 30s，字段只是注释了意图。
2. **收割机注释"research points"名不副实**：System.cs:19 注释称"转化为 OWN research points"，但 Points 是独立字段，与科技树研究点（RND）完全隔离——不共享、不结算进科技。玩家若按注释理解会误以为产出研究点。
3. **蓝水晶手动使用 = 传送自己**（不是传送别人）：UseInHand 的 target 是 `args.User`（System.cs:33），落地只驱逐不传送（target 为 null，:54 判空）——"拿蓝水晶砸地驱影裔"的用法与"砸人传走"的用法并存，文档/直觉容易只记后者。
4. **20 次落点尝试无最终兜底**：循环若 20 次全撞静态物，会用最后一次偏移坐标（System.cs:57-62）——理论上可能把目标传进墙/窗（低概率，无二次校验）。
5. **蓝空间植入体 = 自杀/销毁装置**：激活或死亡即删除使用者身体（DeleteOnTrigger targetUser），"传送"只是特效叙事——没有目的地，玩家直接变幽灵。导师鼠死亡时身体消失的"传送走"其实是删实体。
6. **官方层 3 种蓝空间袋/手持传送器星光零改动**：仅 hand_teleporter 描述被星光改写（`# SL`），机制沿用官方 Portal 组件——"蓝空间科技"在官方层本就有基础，星光在其上加了自己的晶体/收割机/植入体体系。
7. **低温传送与官方 cryo 的叠加口径**：星光"低温传送"只是把身体送入官方低温存储的**触发器**；玩家真正"下机"（保留身体、归还槽位）的行为全在官方 CryostorageSystem——两系统共用 `CryostorageContainedComponent` 防重复传送（CryoTeleportationSystem.cs:65）。
8. **UncryoableComponent 排除未在站内说明**：AI/特殊实体即使离开 7 分钟也不会被传送（CryoTeleportationSystem.cs:66），站内公告文案未区分。
9. **`TODO: Change this?`**：BluespaceCrystalSystem.cs:17 特效实体名 `EffectFlashBluespace` 带 TODO 注释——实现者自己也不确定是否沿用官方闪光特效。
10. **裂隙怪物名称诡异**：MiGo 显示名就叫 "Creature"、Otherthing 叫 "otherthing"（hellmobs.yml:37,113）——实体 id 是 MobBluespaceHarvesterMiGo 但显示名未本地化，zh-CN locale 亦无对应词条。
