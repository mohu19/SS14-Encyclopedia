## 总览

恶魔（Devil）是星光服务器自研的反派职业：外勤特工以"地狱契约"诱骗船员签字，用**罚约（Damnation）**换取灵魂，收集灵魂会触发恶魔外貌逐级进化。核心机制全部集中在 `DevilSystem`（Server 3 分部类 + Shared 基类）与 20 个罚约原型中。

**一句话数值速览**：契约总成本 ≤ 0 才有效（`SharedDevilSystem.cs:69`）；真名驱逐 = 基因 6 + 精力 40/次、每人 3 秒冷却（`DevilComponent.cs:112-136`）；受诅者念真名 = 150 热伤 + 引燃 + 5 秒击倒（`DevilSystem.Damned.cs:30-35`）；恶魔自愈 15 分钟冷却且**不治基因伤**（`rejuvenate.yml:28-30`）；牧师圣经处决 = 基因 777 + 不可复活（`DevilComponent.cs:142-148`）；进化阈值 1/3/4/5/6/7 灵魂（`DevilComponent.cs:85-100`）。

### 2.3 成本平衡规则

1. **总成本必须 ≤ 0**：契约解析时累加各罚约 `cost`（`SharedDevilSystem.cs:132-133`）；签署校验 `content.Cost > 0` 判为 `TooCostly` 拒绝（`SharedDevilSystem.cs:69-70`）。**负成本=地狱方盈利**。
2. **使用次数上限**：`maxUses == -1` 无限；否则累计 `DamnationUsage` 超限判 `OverusedDamnation` 拒绝（`SharedDevilSystem.cs:76-81`）。全局限 1 次 = Terminator，限 2 次 = Magic。
3. **拼写错误**：无法匹配罚约名称的条款进 `InvalidDamnations`（不计成本、不生效），契约名变"拼写错误的地狱契约"、纸张变空白外观，但**仍可签署**（`SharedDevilSystem.cs:122-127, 206-210`）；空白 `[form]` 字段被忽略（`InfernalContractComponent.cs:23`、`SharedDevilSystem.cs:122`）。
4. **罚约名称匹配是英文**：条款按 `_damnations[d].Name.ToLower()`（yaml 内英文名，如 "my soul"）逐条比对（`SharedDevilSystem.cs:116-121`）。
5. 目标作弊防护：`Time` 罚约 `reverseOnRemove: false`——无法通过撤销机制刷分（`damnations.yml:59`）。

### 2.4 签署流程与限制

| 规则 | 实现 | 来源 |
|---|---|---|
| 只有恶魔（作者）能编辑契约 | 非作者写入被 `Cancelled`（"你的手穿过了契约"） | `SharedDevilSystem.cs:154-161` |
| 恶魔/受诅者/机器人（borg）**不能签署** | `HasComp<DevilComponent> || HasComp<DamnedComponent> || HasComp<BorgChassisComponent>` → 拒绝 | `SharedDevilSystem.cs:176-181` |
| 签署校验 | 格式有效 + 成本 ≤ 0 + 未超 maxUses，否则"契约灼伤你的手" | `SharedDevilSystem.cs:163-172` |
| 签署生效 | 立即 `DamnEntity`（一次性施加全部罚约），契约标记 `Completed` 不可再用 | `SharedDevilSystem.cs:188-191` |
| 施加失败回滚 | 任一罚约失败 → `DamnationInitFailEvent` → 全部撤销 + 移除 DamnedComponent + "契约告吹"弹窗 | `SharedDevilSystem.cs:288-296, 333-341` |
| 施加顺序 | 先校验全部可施加，再逐个添加组件/动作；成功才累计 `DamnationUsage` | `SharedDevilSystem.cs:227-259, 276-296` |
| 受诅者状态 | `DamnedComponent`：记录罚约列表、净成本 `NetCost`、施咒恶魔 `DamnedBy` | `DamnedComponent.cs:13-17` |

### 3.2 驱逐念诵（对恶魔）

条件：任意**非恶魔、非受诅者**在同一句话中同时包含【真名】+【6 个驱逐短语之一】（`DevilSystem.Banish.cs:50-54`）。驱逐短语来自 `DevilBanishPhrases` 词典（`count: 6`，`banish_dataset.yml`），中文本服为：**停下 / 住手 / 滚开 / 离开 / 终止 / 放弃**（`banish-phrases.ftl`，英文原版 stop/halt/begone/leave/cease/give up）。

| 项目 | 数值 | 来源 |
|---|---|---|
| 每次驱逐伤害 | **基因（Cellular）6** | `DevilComponent.cs:124-130` |
| 每次精力伤害 | **40 精力**（100 精力=击倒，约 2.5 次念诵即倒地） | `DevilComponent.cs:136` |
| 每人冷却 | **3 秒**（每人对恶魔独立计时） | `DevilComponent.cs:112` |
| 伤害类型 | 基因伤害——**恶魔自愈不覆盖基因**（见第四章），积少成多无法自疗 | `rejuvenate.yml:30` |
| 触发音效 | 驱逐成功无指定音效；恶魔端无提示（todo 注释"触发搞笑表情"） | `DevilSystem.Banish.cs:60` |

多人齐念 = 每人独立 3 秒冷却，可多线程叠加精力伤害 → 快速击倒→处决。Guidebook"只需几个人齐声念诵，就能让你走向毁灭"成立。

## 十一、疑点清单

1. **目标计数逻辑疑似取反**（`DamnConditionSystem.cs:32`）：`damnedComp.Damnations.Except(RequiredDamnations).Any()` 只统计"罚约集合**包含 Soul 之外其他罚约**"的受诅者——纯 Soul 契约的受害者**不计入**"诅咒 7 个灵魂"进度，与目标描述（诅咒灵魂）不符，疑为应为 `!…Except…Any()`（统计至少含 Soul 者）。
2. **UI 文案 vs 代码口径**：诅咒之书 UI 写"代价之和必须**低于零**"（`ui.ftl`），代码实际允许 `cost == 0`（仅 `> 0` 拒绝，`SharedDevilSystem.cs:69`）——Guidebook"≤0"与代码一致，UI 文案偏严。
3. **Humanity（变猴子）罚约定义但未启用**：yaml 有 `Humanity`（cost -5，IrreversibleMonkey）与 `TestFail`，但不在 `DevilComponent.AvailableDamnations`（`DevilComponent.cs:27-47`）——恶魔游戏中无法开出"变猴子"条款。
4. **中文本地化断层（高风险）**：契约解析正则（`contract.yml:25-28`，英文 "i offer the following:"）与罚约名匹配（yaml 英文名 "my soul" 等）均硬编码英文；zh-CN 契约模板（`infernal-contract.ftl`）为中文（"本人将以下事物："）。若服务器以中文渲染模板，默认模板将无法通过格式校验（InvalidFormat），**恶魔必须手动把契约改写为英文关键字**才能签署。
5. **Jaunt 描述口径**：动作描述"5 minute recharge" vs 代码 150 秒/充能×2 充能——2.5 分钟/次，满充 5 分钟；单次充能周期比描述短一半。
6. **逐字小字条款与真名正则**：契约必填模式要求原文逐字匹配（含 `[bold]` 标记），玩家改写模板时若损坏小字，契约直接 InvalidFormat——恶魔不能为了"防读真名"而删掉真名句（真名正则 `(?<={真名}, an agent of hell.).*` 会失效导致格式非法）。
7. **TestFail 残留**：`DamnationActionFail` 源码注释 "test class"（`DamnationActionFail.cs:3`），测试原型 `TestFail` 仍保留在原型库中。
8. **灵魂收集无视觉特效**：受诅者死亡时灵魂"入地狱"仅体现为 Unrevivable + SoulDebt 警报，无动画/事件表现。
