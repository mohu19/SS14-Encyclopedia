## 一、系统概述：什么是零空间

零空间（NullSpace）是星光 fork 基于**可见性分层（Visibility Layer）**实现的"相位维度"：拥有 `NullSpaceComponent` 的实体从常规渲染层（`VisibilityFlags.Normal`）剥离，挂到专用渲染层 `VisibilityFlags.NullSpace`（**层值 32 = 1<<5**，`Content.Shared/Eye/VisibilityFlags.cs:14`，注释明示"Nullspace Ents, Brighteyes, Revenants, Cosmic Cult"），从而**只被"能看见零空间"的观察者看到**。

零空间不是一张独立地图（那是"黑暗界 The Dark"，见 §十），而是**叠加在实体空间上的不可交互状态**：相位中的实体仍停留在原坐标，但普通玩家既看不见也摸不着；零空间观察者（虚无空间护目镜、NTSF 头盔、宇宙邪教成员、回响幽灵等）看得见，但**同样无法攻击/交互**（§7.4）。其本质是"两界互不可及，只有零空间内部可以互相作用"。

零空间的"常住客"：

| 群体 | 进入方式 | 依据 |
|---|---|---|
| 明眼者（Brighteye）相位 | 相位能力（能量消耗） | `ShadekinSystem.Abilities.cs:181-223` |
| 被明眼者拖入的目标 | 10s 引导后随行 | `ShadekinSystem.Abilities.cs:205-237` |
| 回响幽灵（Revenant） | 天生驻留（星光改动） | `revenant.yml:74-75` |
| 宇宙邪教星界投影 | 天生可见（非驻留） | `astralforms.yml:25-31` |

## 三、进入零空间：相位（Phase）机制

### 3.1 相位能力的来源

- 通用相位动作 `NullPhaseAction`（"Phase Shift / 相位转移"）：`useDelay: 1`（`Actions/shadekin.yml:1-14`）。由 `NullPhaseSystem.Toggle` 在持有 `NullPhaseComponent` 的实体上 `AddAction`（`NullPhaseSystem.cs:83-89`）。
- 明眼相位动作 `BrighteyePhaseAction`（父级 `NullPhaseAction`，**整体覆写 `Action` 组件**：仅 icon/checkCanInteract/NoItem，无 useDelay）：由明眼系统授予（`Brighteye.cs:51`）。
- ⚠️ **通用 `NullPhaseComponent`/`NullPhaseAction` 当前为死代码**：全 yaml 无任何实体携带 `NullPhaseComponent`，全代码库除 `NullPhaseSystem` 自身的穿戴复制（`NullPhaseSystem.cs:58`）外无 `EnsureComp` 授予点——实际相位全部走明眼动作链。见疑点 ①。

### 3.2 CanPhase：相位许可检查（`NullPhaseSystem.cs:91-145`）

**未相位 → 进入零空间**，任一条件不满足则弹 `phase-fail-generic` 失败提示：

1. 处于容器内（`_container.IsEntityInContainer`，:106）
2. 脚下存在 `NullSpaceBlockerComponent` 实体（阻断器力场，:113-120）
3. 身上任何装备槽（含背包内物品）或其容器内藏有 `MobStateComponent` 实体——**禁止携带活物相位**（:123-141）

**已相位 → 离开零空间**：若脚下瓦片存在 `Impassable` 碰撞实体则失败并弹 `revenant-in-solid`（卡在固体里出不来，:93-102）。

### 3.3 相位切换流程（`NullSpaceSystem.cs` + `NullPhaseSystem.cs:147-189`）

**进入（Phase 于未相位实体）**：`EnsureComp<NullSpaceComponent>` → `OnStartup`（`NullSpaceSystem.cs:56-111`）：

1. **渲染层切换**：移除 Normal 层、挂 NullSpace 层并刷新可见性（:58-63）
2. **隐身值**：`Stealth.SetVisibility(0.8f)`（:65-66，见疑点 ⑥）
3. **派系抑制**：NPC 阵营全部移除并存入 `SuppressedFactions`（:68,175-194）
4. **站起来**：`RemComp<KnockedDownComponent>`（:70）
5. **挂免疫**：`PressureImmunity` + `FTLSmashImmune` + `TemperatureImmunity`（:72-74）
6. **失重处理**：`RefreshWeightless(false)`——相位中不失重（:76-77）
7. **清空双手**：所有手持物品强制丢落（`Unremoveable`/虚拟物品除外），并在每只手生成**不可移除虚拟物品**（:79-103）
8. **拖拽处理**：若正被"物理界"实体拖拽则强制断开；若拖拽者是零空间实体则跟随（:105-110）

**特效**（`NullPhaseSystem.cs:149-188`）：影裔进出时 5 格内电灯触发 `GhostBooEvent`（灯闪烁），并生成 `ShadekinPhaseInEffect`/`ShadekinPhaseOutEffect` 特效（0.5s，`Effects/shadekin.yml:40-84`）；非影裔生成 `ShadekinShadow` 暗影迷雾（30s 消散、紫色 `#793a80dd`，`Effects/shadekin.yml:1-38`）。⚠️ 代码语义：**进入播放 PhaseOut、离开播放 PhaseIn**——命名与方向相反，见疑点 ⑤。

**离开（Phase 于已相位实体）**：`RemComp<NullSpaceComponent>` → `OnShutdown`（`NullSpaceSystem.cs:113-132`）：

1. 渲染层切回 Normal（:115-120）
2. 派系恢复（:122）
3. 移除 `Stealth`/`PressureImmunity`/`FTLSmashImmune`（:124-126）
4. **温度免疫保留**——除非该实体关联 3 阶宇宙邪教规则（:128-129，见 §十与疑点 ③）
5. 删除双手虚拟物品（:131）→ 触发 `OnVirtualItemDeleted`：若虚拟物品对应的被拖拽实体仍在零空间，则将其一并相位切出（:142-167，注释"别把零空间的东西拖出来"的配套安全逻辑）

### 3.4 拖拽他人进入零空间（`ShadekinSystem.Abilities.cs:205-237`）

明眼者拖拽着目标时使用相位：进入 **10s DoAfter 引导**（`TimeSpan.FromSeconds(10)`，受伤/移动/换持物即打断，:212-217）→ 完成后目标被挂 `NullSpacePulledComponent` 标记（:233）→ 明眼者相位 → `OnStartup` 检测到手部虚拟物品指向带标记且正在被拖拽的实体，将其**一起拉入零空间**（`NullSpaceSystem.cs:88-95`）。离开时同理同步切出（:142-167）。

## 五、离开零空间

### 5.1 主动离开
再次使用相位动作（能量消耗规则见 §3.1 与 `ShadekinComponents.cs:144`：PhaseCost 默认 **50**；光照档位缩放 Low×2=100 / Annoying×3=150 / High=全额 MaxEnergy(200) / Extreme 禁用；**零空间内离开免费**，`Abilities.cs:184-191` + `Brighteye.cs:271-280` cost=null 免扣）。

### 5.2 强制驱逐：NullSpaceShunt（`NullSpaceSystem.cs:169-173`）
对相位实体触发 `NullSpaceShuntEvent`（定义于 `BluespaceCrystalComponent.cs:32`）→ 生成暗影迷雾 + `RemComp` 强制踢出零空间。触发源：

| 来源 | 范围/数值 | 依据 |
|---|---|---|
| **蓝移水晶**（使用/落地/投掷命中） | 以水晶为中心 **8 格内全体零空间实体**被驱逐（`NullSpaceShuntRange=8`）；同时范围内有 Mob 目标则随机传送（`Range=8`，最多 20 次尝试避让静态物） | `BluespaceCrystalComponent.cs:9-28`、`BluespaceCrystalSystem.cs:48-77` |
| **心灵尖啸**（PsychicScreach 站内事件） | 选中空间站上**全部活体**（Dead 除外）被驱逐 | `PsychicScreachRule.cs:94-96` |
| **虚空抹除**（宇宙邪教能力 CosmicBlank） | 目标在零空间 → 先驱逐再执行抹除引导；施法者处于阻断器范围内则失败 | `CosmicBlankSystem.cs:56-71` |

**驱逐惩罚**：影裔额外 **击倒 1s + 核心 5 细胞伤害**（`ShadekinSystem.cs:132-140`）；明眼者**能量清零**（`Brighteye.cs:169-173`）；普通实体无副作用。⚠️ 注意"蓝水晶失稳"叙事在代码侧仅此一条路径，见疑点 ④。

### 5.3 碰撞解除（UnphaseOnCollide）
相位实体与 `NullSpaceBlockerComponent`（默认 `UnphaseOnCollide=true`，`NullSpaceBlockerComponent.cs:19`）实体发生碰撞 → 强制移除相位 + 暗影迷雾（`NullSpaceBlockerSystem.cs:34-50`）。

## 十、与影裔 / 明眼 / 超物质的关联

## 十二、疑点清单

1. **通用相位是死代码**：`NullPhaseComponent`/`NullPhaseAction`（含 zh-CN 译名"相位转移"）在 yaml 与代码中均无授予方，仅 `NullPhaseSystem` 的穿戴复制自循环——当前没有任何实体实际获得"通用相位"，全部相位走 `BrighteyePhaseAction`/`BrighteyePhaseActionEvent`。疑为旧版影裔相位系统残留。
2. **Lambda 粒子实为 Sigma**：`CosmicLambdaParticle` 的 `AnomalousParticle.particleType` 是 `Sigma`（`projectiles.yml:256-258`），命名与类型不一致。
3. **OnShutdown 温度免疫分支多为 no-op**：进入零空间时已挂 `TemperatureImmunity` 且离开时不删除，`:128-129` 的"非 3 阶邪教则 EnsureComp"仅在邪教转化流程主动删除过该组件的场合（`CosmicCultRuleSystem.cs:960`）才有实际意义。
4. **蓝水晶"失稳"无独立状态**：叙事上蓝水晶使零空间"失稳"，代码侧只有 `NullSpaceShuntEvent` 一条路径（击倒/伤核心/清能量/弹出），无失稳计时器等独立机制。
5. **相位特效命名方向相反**：进入零空间播放 `ShadekinPhaseOutEffect`（消失）、离开播放 `ShadekinPhaseInEffect`（现身）——以观察者视角命名，与代码变量名 phase-in/out 语义相反，易误读。
6. **"隐形"是双保险**：相位实体既有 vis 层过滤又有 Stealth 0.8（接近满显），对普通玩家实际不可见完全依赖 vis 层；Stealth 0.8 的作用场合（如对零空间观察者的可见度）代码未明示。
7. **明眼相位无冷却**：`BrighteyePhaseAction` 整体覆写父级 `Action` 组件，父级的 `useDelay: 1` 不继承（SS14 yaml 组件继承为整块替换）——明眼相位仅靠能量节流（推断结论，未在代码中直接声明）。
8. **抽取器"阻断进出"是叙事**：道具描述宣称"限制实体进入或离开零空间"，机制上只有能量封锁（技能取消）与黑暗界免疫，无直接相位阻断效果。
