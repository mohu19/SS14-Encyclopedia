## 一、系统概述

星光服务器（STARLIGHT fork）的异星生物（Xenobiology）系统是 **星光自研系统，官方层零代码**——`SlimeComponent` 等全部只出现在 `Content.*/_Starlight/Xenobiology/`（grep 全库验证，官方层仅存在不含该组件的普通史莱姆生物 `MobAdultSlimes`，见 §15）。

玩法闭环：**获取灰色史莱姆 → 喂猴子/分裂扩群 → 变异出新颜色 → 处理器榨取提取物 → 提取物 + 水/血/等离子触发反应 → 产出药水/资源/生物**。控制台（遥控眼）提供远程操作，摄像头标记器扩展视野。

## 三、分裂与突变机制

核心逻辑 `Content.Shared/_Starlight/Xenobiology/SlimeSystem.cs`：

- **分裂触发**：HTN 行为树在"不饿"（饥饿状态 ≥ Okay）时执行 `SlimeSplitOperator`，**每只分裂为 4 只**（`xeno_slimes.yml:23` `splitAmount: 4`；`SlimeSplitOperator.cs:16-17`）。
- **分裂队列**：`QueueSlimeSplit` 入队，`Update` 每 tick 统一处理（`SlimeSystem.cs:36-45, 114-118`）。
- **分裂规则**（`SlimeSystem.cs:78-112`）：
  1. 每只子史莱姆营养 = 母体营养 / 分裂数（:82-83）；
  2. 突变概率 **原样继承**（:106）；
  3. 产物判定（:87-100）：突变概率 ≥ 1.0 且配置了 `mutationOnMaxSplit` → 直接变**彩虹**；否则掷随机数 < 突变概率 且突变列表非空 → 从列表随机选 1；否则 → `splitInto`；
  4. 母体删除（:110）。
- **进食**（`TryEat`，:53-76）：目标需在 **0.75 格**内无遮挡（:57）、有 `Damageable`（:58）；伤害**无视抗性**（`ignoreResistances: true`，:60）；实际造成正值伤害才获得营养（:70-73）；播 bite 音效 + 咬合动画（:61-68）。

### 突变概率操作手段

| 手段 | 效果 | 上限/下限 | 出处 |
|---|---|---|---|
| 突变药水（手持/控制台） | +**0.12**/瓶 | 上限 1.0 | `SlimeMutationPotionComponent.cs:8` |
| 稳定药水（手持/控制台） | **−0.15**/瓶 | 下限 0 | `SlimeStabilizerPotionComponent.cs:8` |
| 分裂继承 | 子代保留母体概率 | — | `SlimeSystem.cs:106` |

> 100% 概率时分裂必出彩虹（`mutationOnMaxSplit`，`SlimeComponent.cs:55-56`），这是获得彩虹史莱姆的唯一定向途径；普通突变命中也只从 `splitIntoMutation` 列表选（`SlimeComponent.cs:48-49`）。

## 四、史莱姆行为（HTN 蜂巢脑）

### 4.1 行为树 `SlimeMainCompound`

`Prototypes/_Starlight/NPCs/xeno_slimes.yml:1-41`，分支按优先级：

1. **不饿时**：随机等待（`RandomOperator` 取 IdleTime）→ 等待 → **分裂 4 只**（前提：`NotHungryPrecondition` 饥饿 ≥ Okay）；
2. **饿时**：`SlimeEatCompound`（:43-78）——HungryPrecondition → 选目标 → 移动范围 0.5 → 移动 → `SlimeEatOperator` 进食 → 等待 1s；
3. **找食**：`SlimeFindEdibleTargetOperator`（`targetFoodTag: Monkey`）——5 格内找带 `Monkey` 标签目标；
4. **闲逛**：`IdleCompound`。

> `SlimeGoToFeedingSpotCompound`（喂食点导航）整段被注释禁用（:34-37），开发者注释承认 `MoveToOperator` 只能移到实体不能移到坐标（:80-84）——"记忆喂食点"功能已实现但**未接入行为树**（见疑点 §16-4）。

### 4.2 可食判定（蜂巢脑共享规则）

`Content.Server/_Starlight/Xenobiology/SlimeBrainSystem.cs`：

| 规则 | 数值 | 出处 |
|---|---|---|
| 觅食半径 | **5 格**（`FoodSearchRange`） | :52 |
| 目标伤害上限 | 总伤害 < **100** 才可食（`TargetDamageThreshold`） | :57, :81 |
| 伤害容器 | 必须为 `Biological`（`OnlyTarget`） | :63, :76-78 |
| 硬性排除 | 有 `SlimeComponent`（不吃同类）、无 `Damageable`、无 `MobState`（非生物） | :68-74 |

- **喂食点记忆**：吃到食物→记下坐标（`SlimeSuccessfulEat` :150-151）；到达后找不到食物→移除（`SlimeUnsuccessfulFoodFind` :157-158）。坐标集合全群共享。
- **目标共享**：`_targetFood` 全局集合——任何史莱姆发现可食目标，全体共享（`TryAddTargetFood`/`AcquireTargetFoods` :91-126）。

### 4.3 "蜂巢思维"设计注释 vs 实现（重要差异）

`SlimeBrainSystem.cs:11-25` 的头部注释描述了一个宏大设计：情绪（Mood）驱动行为、好感度（-100~100）记忆、听命于喜爱的个体、仇杀厌恶者、情绪随事件迁移……但 **实际代码只实现了共享食物目标集 + 喂食点记忆**。`SlimeMood` 枚举（:27-31）只有 `Calm`/`Desperate` 两值且**全库无消费方**（grep 验证）——情绪/好感度系统是未实现的半成品（见疑点 §16-1）。

## 六、提取物反应引擎

### 6.1 组件与容器

`Entities/Objects/Specific/Xenobiology/extracts.yml:1-25`：所有提取物自带溶液容器 **maxVol 150**（容器名 `container`）、`MixableSolution`/`DrawableSolution`/`InjectableSolution`（可混合、可抽取、可注射）、体积 Tiny、`SlimeExtract` 组件。

- 剩余使用次数：默认 **1**（`SlimeExtractComponent.cs:27`），可用提取物增强药水 +1。
- 检视提示"剩余/耗尽"（`SlimeExtractSystem.cs:131-141`，zh-CN：史莱姆提取物冒着充满生机的气泡！…已耗尽…）。

### 6.2 反应触发流程

`Content.Shared/_Starlight/Xenobiology/SlimeExtractSystem.cs`：

1. **检测**：溶液每次变化（`SolutionContainerChangedEvent`）检查各反应需求（如 `Water: 5`）是否满足（:55-75）；满足 → 登记 `ActiveReactions[proto] = 当前时间 + Delay`；
2. **等待**：到时后复查需求仍满足（:87-91）；
3. **消耗**：按**最小缩放因子**消耗——`min(每种试剂容器量/需求量)`（`FindMinimumScalingFactor` :44-53），每种试剂扣 `最小因子 × 需求量`（:94-99）；
4. **效果**：效果强度 = `最小因子 × scalingFactor + scalingOffset`（:102；公式定义 `ExtractReactionPrototype.cs:46-53`）；
5. **计数**：触发一次 `RemainingUses −= 1`（:112）；`shouldDelete: true` 且用完 → 删除（:113-116）；
6. **暂停**：实体暂停时反应计时顺延（:120-129）。

> 反应原型 `ExtractReactionPrototype`（`ExtractReactionPrototype.cs:12-41`）：`requirements`（试剂需求）/ `effects`（缩放效果列表）/ `shouldDelete`（是否消耗次数并最终删除）/ `delay`（延迟）。

### 6.3 反应类型一览

| 效果类型 | 说明 | 实例 |
|---|---|---|
| `AddReagentToSolution` | 向容器注入试剂（按缩放） | 灰+水→肾上腺素 |
| `SpawnEntity` | 生成实体（数量固定） | 灰+血→3 猴子方块 |
| `CreateGas` + `AddHeat` | 生成气体/加热（缩放） | 橙+等离子→等离子+氧气+加热 50000 |
| `Explosion` | 爆炸（`Default` 型） | 油+等离子 |
| `SpawnEntityFromTable` | 从随机表生成 | 银/金/彩虹提取物 |
| `AddHeat` 负值 | 吸热降温 | 深蓝+等离子→氮气+吸热 −3000 |

## 十六、疑点清单

1. **"蜂巢思维"半成品**：`SlimeBrainSystem.cs:11-25` 注释详述情绪/好感度（-100~100）/爱憎追杀/听令设计，但代码仅实现共享食物目标 + 喂食点记忆；`SlimeMood` 枚举（:27-31）仅 `Calm`/`Desperate` 且全库无消费方。
2. **防火药水死字段**：`SlimeFireproofPotionComponent.FireproofDamageSet`（`SlimeFireproofPotionComponent.cs:19-20`）在 `SlimeFireproofPotionSystem` 中**从未被读取**；且指向的 `SlimeFireproofPotionEffect` 是 `Heat: -10.0` **负系数**（`Damage/modifier_sets.yml:133-135`）——若未来被应用，按本 fork"负伤害=治疗"语义会变成受热反治疗（结合 §6.2 若用错语义将反转）。
3. **喂食点导航未接线**：`SlimeGoToFeedingSpotCompound` 注释禁用（`xeno_slimes.yml:34-37`），开发者自认 `MoveToOperator` 无法移到坐标（:80-84）——脑系统记忆的喂食点实际无行为树消费。
4. **黑色史莱姆产出矛盾**：`XenobiologySlimeBlack` 的 extract 是 `OilSlimeExtract`（`xeno_slimes.yml:341`），而独立实体 `BlackSlimeExtract`（黑提取物，`extracts.yml:830-851`，产高级变异毒素）**没有对应黑色史莱姆产出**——玩家只能靠彩虹提取物随机表/预填充获得黑提取物。
5. **黄色 EMP 反应禁用**：`extracts.yml:345-354` 注释"EMP 系统重做前是坏的"——黄色提取物 + 血原本产出 EMP，现不可用。
6. **天蓝血反应悬置**：`extracts.yml:569` 注释"控制台实现前不生效"，但控制台已实现（§10）——此反应仍未启用，疑似遗漏。
7. **红/粉提取物缺反应**：红血反应（狂犬病 rabidity）与粉等离子反应（温顺 docility）注释"需先实现"（:647, :722）——对应能力未实现。
8. **彩虹镭反应试剂不符**：`extracts.yml:961` 注释"应该是史莱姆凝胶但未实现"，现用镭代替。
9. **收割门槛与描述**：处理器描述"Try freezing them first!"（`slime_processor.yml:5`）与代码条件"总伤害 ≥ 200"（`CollectingSlimeProcessorSystem.cs:175`）对应——冻伤/殴打均可，但不需真正死亡（有 MobState 阈值机制，死亡状态史莱姆同样满足条件）。
10. **无游戏内教学**：Guidebook 全库无异种生物学条目（grep `xenobio|slime` 于 Guidebook 目录仅命中物种条目 SlimePerson）——机制仅靠入门箱描述传达。
11. **提取物缩放公式**：反应强度 = `min(各试剂含量/需求) × scalingFactor + scalingOffset`（`ExtractReactionPrototype.cs:49-53`）——**倒入越多同比例试剂，产出越大**（如橙色水反应 ×10 的 OrangeSmokeCauser，需求 5、容器 150，理论最多 ×300 因子）。
