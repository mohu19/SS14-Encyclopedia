## 0. 命名真相（先说清）

**本 fork 的"异星考古"没有 SS13 式的挖掘流程——没有地层、没有铲子/镐、没有逐层发掘。** SS14 把"挖掘"整体替换为**节点树解谜**：遗物内部是随机生成的节点图（graph），玩家通过分析仪/控制台查看节点与触发条件，在遗物旁完成条件"解锁节点"，解锁即激活效果，之后可手动反复激活（消耗耐久度）刷效果与研究点数。Guidebook 概述（`Xenoarchaeology.xml`）与解锁流程（`UnlockingNodes.xml`）均围绕此玩法，任务书假设的"工具/地层"不成立。

**获取遗物的途径**（Guidebook `Xenoarchaeology.xml:8-12`）：
- 回合开始科研部实验室 1-2 件（地图生成，Maps 目录未在稀疏克隆中，无法核实具体地图点位）
- 货运订购：`RandomArtifact` 2000 信用点（`Resources/Prototypes/Catalog/Cargo/cargo_science.yml:22-28`）
- 打捞发现：官方 `salvage_loot.yml:58` + 星光三层打捞 `_Starlight/Procedural/salvage_loot_{easy,moderate,challenging}.yml`、打捞奖励表 `salvage_rewards.yml:15`（权重 0.25）、蓝移收割机奖池 `bluespace_harvester_pools.yml:43`
- 地牢掉落：`_Starlight/Procedural/dungeon_configs.yml:380`（`RandomArtifactSpawner20`，20% 概率）
- 碎片组装：4 块遗物碎片 + 5 秒工序 → 新遗物（见 §8.5）
- 站内事件/随机刷怪器：`RandomArtifactSpawner`（结构/手持 2:1，`Markers/Spawners/Random/artifacts.yml:1-7`）

### 1.2 节点图生成（MapInit 时，`XenoArtifactSystem.cs:19-23` → `XenoArtifactSystem.ProcGen.cs`）

| 参数 | 默认值 | 来源 |
|---|---|---|
| 节点总数 NodeCount | 10-16（组件默认）；Complex 实体覆写为 **9-13** | `XenoArtifactComponent.cs:115`；`structure_xenoartifacts.yml:49-51` |
| 段大小 SegmentSize | 5-8，**强制至少 2 段**（代码保证单件遗物 ≥2 个互不相连的节点树） | `XenoArtifactComponent.cs:122`；`ProcGen.cs:200-218` |
| 每层节点数 NodesPerSegmentLayer | 1-3（随迭代深度递增偏移 `iteration/1.5`） | `XenoArtifactComponent.cs:128`；`ProcGen.cs:151-159` |
| 每层随机散射边 ScatterPerLayer | 0-2 条额外边 | `XenoArtifactComponent.cs:134`；`ProcGen.cs:186-192` |

生成算法（`ProcGen.cs:14-27`）：
1. 掷节点总数 → 建**触发池**（CreateTriggerPool，:38-63）：从 `DefaultTriggers` 权重表里**无放回**地随机抽触发器，每个触发器在单件遗物上至多出现一次；池不够时按实际数量缩水并报错（:47-51）
2. 分段递归生成（PopulateArtifactSegmentRecursive，:140-195）：先造顶层（depth 0），逐层向下，后继层每节点随机挂到前层某节点下，再补散射边
3. 若递归产生多个不连通块，用"深度范围匹配"随机补边合并（:79-132）
4. 每个节点 = 一个 `XenoArtifactNodeComponent` 实体（藏在遗物容器 `node-container` 内），从效果表中抽 1 个效果挂上去（`Node.cs:98`），并打上触发器组件（`Node.cs:107`）

> ⚠️ **权重表形同虚设**：CreateTriggerPool 用 `RobustRandom.Pick(weightsByTriggersLeft)`（`ProcGen.cs:53`）对字典**均匀抽键**，`triggers.yml` 里 0.1~1 的权重值**不影响任何概率**（详见疑点 1）。

### 1.3 节点 ID 与图结构

- 节点实体带 `NameIdentifier`（组 `XenoArtifactNode`，`name_identifier_groups.yml:45`），控制台/扫描仪显示为 **3 位编号**（如 001、042，`Node.cs:174-177`）
- 图结构 = 顶点数组 + 邻接矩阵（`XenoArtifactComponent.cs:94-106`），方向"前驱 → 后继"，解锁必须**所有直接前驱已解锁**（`Node.cs:113-131`）
- **活跃节点（Active）定义**：已解锁、且**没有任何已解锁后继**（即每棵树当前路径末端，`Node.cs:260-299`）——手动激活时只激活这些节点

## 2. 节点耐久度与"研究价值"

### 2.1 耐久度（Durability）

| 参数 | 默认值 | 来源 |
|---|---|---|
| MaxDurability | **5**（组件默认）；效果实体各自覆写：一次性 1、普通 2-7 | `XenoArtifactNodeComponent.cs:53`；`effects.yml` 各实体 |
| MaxDurabilityCanDecreaseBy | 0-2（组件默认），实体覆写 0-0 ~ 0-5 | `XenoArtifactNodeComponent.cs:59` |
| 实际最大耐久 | MapInit 时 `MaxDurability -= 随机(0..MaxDurabilityCanDecreaseBy)` | `Node.cs:32` |

- **手动激活一次扣 1 点耐久**（`SharedXenoArtifactSystem.XAE.cs:128-131`），耐久归 0 = 节点退化（Degraded），无法再激活（:120-122）
- 耐久可以恢复：**遗物胶水（ArtifactGlue）**涂抹 → 所有活跃节点 +1 耐久（见 §9）

### 2.2 研究价值公式（核心数值）

```
ResearchValue = (int)( 1.25^(前驱总数^1.5) × BasePointValue × durabilityMultiplier )
```
- `BasePointValue = 4000`（`XenoArtifactNodeComponent.cs:67`）
- `durabilityEffect = (Durability/MaxDurability)^2`（`Node.cs:387`）
- **活跃节点**：multiplier = `1 - durabilityEffect`；**非活跃（未解锁）节点**：multiplier = `1 + durabilityEffect`（`Node.cs:388-390`）
- 实际可提取 = `max(0, ResearchValue - ConsumedResearchValue)`（`Node.cs:154-160`）

**实战含义（反直觉，重要）**：
- 未解锁节点满耐久时价值 ×2（8000 点）；**刚解锁的节点满耐久时价值为 0**——必须先手动激活把它耐久打下去，研究价值才涨回来（每消耗 1 点耐久，`(D/Max)^2` 项减小，multiplier 向 1 靠拢）
- 前驱越多价值指数上涨：1.25^(n^1.5)——0 前驱 ×1.00、1 前驱 ×1.25、2 前驱 ×2.00、3 前驱 ×3.81、4 前驱 ×9.31、5 前驱 ×28.6（n = 全部递归前驱数）
- 深度 0 节点例：满耐久未解锁 = 4000 × 2 = 8000 点；深度 3（3 前驱）未解锁 = 4000 × 3.81 × 2 ≈ 30,480 点

### 2.3 提取研究点

分析控制台"提取"按钮（`Content.Server/Xenoarchaeology/Equipment/ArtifactAnalyzerSystem.cs:26-49`）：遍历**全部已解锁节点**，把各自的 `GetResearchValue` 累加 → 标记为已消耗（SetConsumedResearchValue）→ `ModifyServerPoints` 注入控制台绑定的研究服务器。≤0 时不注入（:42-44，注释吐槽"科学家做出负 5000 研究"）。**解锁所有节点无额外奖励**（Guidebook 明示）。

**遗物出售价** = Σ(已解锁节点 ResearchValue) × `PriceMultiplier 0.10`（`XenoArtifactSystem.cs:25-34`、`XenoArtifactComponent.cs:60`）。

## 3. 解锁流程（触发机制，Unlock 状态机）

### 3.1 状态与数值

| 参数 | 值 | 来源 |
|---|---|---|
| 解锁窗口基础时长 UnlockStateDuration | **6 秒** | `XenoArtifactComponent.cs:67` |
| 每个新触发条件追加时长 UnlockStateIncrementPerNode | **+10 秒** | `XenoArtifactComponent.cs:73` |
| 失败/成功后的冷却 UnlockStateRefractory | **5 秒**（冷却内不可再进入解锁状态） | `XenoArtifactComponent.cs:79`；`Unlock.cs:100` |
| 手动激活间隔 | UseDelay（遗物自带） | `xenoartifacts.yml:36` |

### 3.2 流程（`SharedXenoArtifactSystem.XAT.cs:60-96` + `Unlock.cs`）

1. 玩家在遗物旁完成任意**触发器条件** → `TriggerXenoArtifact` 进入解锁状态（弹出"它开始以奇怪的方式变形……"，`artifact-component.ftl:6`），窗口 = 6s；若该触发**合法**（当前已触发集合 ⊆ 该节点前驱∪后继，:83-89），窗口 **+10s** 并记录该节点索引到 `TriggeredNodeIndexes`
2. 解锁窗口结束时（`UpdateUnlock`，`Unlock.cs:25-35`）判定：找出**第一个**满足"已锁定 + 所有前驱已解锁 + 已触发节点集合与（前驱∪自身）**完全相等**"的节点（`Unlock.cs:112-155`）→ 命中则解锁并自动激活一次效果（`Unlock.cs:77-78`，弹出"它逐渐减缓，外观发生了明显变化"，:7）；否则失败（"……无事发生地停了下来"，:8）
3. 无论成败进入 5s 冷却（`Unlock.cs:100`）
4. 解锁窗口期间在别处乱触发其他节点的条件 → 集合多出元素，精确匹配失败 → **该轮必失败**（Guidebook 明示"先做目标节点独有条件"）

> 触发顺序无关紧要（集合匹配不看顺序）；多棵树（段）互不影响（Guidebook `UnlockingNodes.xml`）。

### 3.3 Artifexium 通配机制

遗物上泼 **Artifexium**（来源见 §8.5/§9）：若遗物处于解锁状态则标记 `ArtifexiumApplied`（`ArtifactEntityEffectsSystem.cs:36-51`）。此后判定放宽为"已触发集合 = 必需集合 + **1 个多余节点**"，多余节点作为通配符，从所有候选节点中**随机挑一个**解锁（`Unlock.cs:142-152`）。

## 10. 疑点清单

1. **触发权重表形同虚设**：`CreateTriggerPool` 用 `RobustRandom.Pick` 对字典均匀抽键（`ProcGen.cs:53`），`triggers.yml` 的 0.1-1 权重值不参与概率计算；且触发器每件遗物**无放回**（同触发器不重复出现）。若设计意图是加权随机，此为 bug 或半成品
2. **分析时长是死字段**：`AnalysisDuration = 30s`（`ArtifactAnalyzerComponent.cs:18`）与 `ReadyToPrint`（:38）全仓库无消费方——放上遗物即出图，无扫描等待
3. **研究价值反直觉**：满耐久活跃节点价值 = 0，未解锁节点却 ×2（`Node.cs:387-393`）——新手易在解锁后立即提取吃 0，需先手动激活消耗耐久
4. **Tesla/Singularity 效果实体 id 互换**：`XenoArtifactTesla` 生成奇点、`XenoArtifactSingularity` 生成特斯拉球（`effects.yml:1268-1295`），且权重均注释不入表
5. **TriggerInteraction 定义未启用**（与空手激活/物理伤害冲突，`:20` 注释），TriggerTimer 星光禁用——实际可用触发池 23 种
6. **XATPressureSystem 判定**为 `pressure >= Max || pressure <= Min`（`XATPressureSystem.cs`）——若某触发器同时设两阈值会无条件触发，当前 yaml 均只设一个，属潜在坑
7. 碎片提取的 Artifexium 仅 10u/块，而通配解锁只需 1 次涂抹——粉碎 2-4 碎片够 1-2 次通配，刷 Artifexium 的边际收益有限（设计如此，记录）
8. 本 fork 无"挖掘/地层"玩法，任务书"工具/地层"假设不成立（见 §0 命名真相）
